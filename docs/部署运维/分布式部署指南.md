# LangManus 分布式部署指南

## 🏗️ 架构说明

LangManus 采用**分层分布式架构**：

```
┌─────────────────────────────────────────────────────────┐
│                    用户请求                              │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
        ┌───────────────────────────────┐
        │  Layer 2: Web UI (调度器)     │  ← Docker 容器
        │  - 任务编排                   │
        │  - Agent 调度                 │
        │  - 结果聚合                   │
        └───────────────┬───────────────┘
                        │
        ┌───────────────┼────────────────┐
        │               │                │
        ▼               ▼                ▼
   ┌─────────┐    ┌─────────┐     ┌─────────┐
   │ Agent 1 │    │ Agent 2 │     │ Agent 3 │  ← 远程节点
   │ Node 1  │    │ Node 2  │     │ Node 3  │
   │ 搜索服务│    │ 计算服务│     │ NLP服务 │
   └─────────┘    └─────────┘     └─────────┘
   192.168.1.101  192.168.1.102   192.168.1.103
```

### 关键特性

- **Layer 2 (调度器)**：部署在 Docker 容器中，提供 Web UI 和任务编排
- **Layer 3 (Agents)**：分布式部署在不同的物理/虚拟节点上
- **配置驱动**：通过 `config/agent_registry.json` 管理所有 Agent

## 📋 部署步骤

### Step 1: 在中心节点部署 Web UI (Layer 2)

```bash
# 1. 克隆项目
git clone https://github.com/your-org/langmanus.git
cd langmanus

# 2. 配置环境变量
cp .env.example .env
nano .env  # 填入 LLM API Key

# 3. 启动 Web UI 容器
docker-compose up -d

# 4. 验证启动
curl http://localhost:8000/health
```

### Step 2: 在各个节点部署 Agent (Layer 3)

每个 Agent 节点有两种部署方式：

#### 方式一：使用 Docker（推荐）

```bash
# 在 Node 1 (192.168.1.101) 上部署搜索 Agent
docker pull langmanus/agent-orchestrator:latest

docker run -d \
  --name search-agent \
  --restart unless-stopped \
  -p 8080:8080 \
  -e AGENT_ID=search_agent_001 \
  -e AGENT_CAPABILITY=search \
  -e TAVILY_API_KEY=your_tavily_key \
  langmanus/agent-orchestrator:latest \
  python agent_server.py 8080

# 在 Node 2 (192.168.1.102) 上部署计算 Agent
docker run -d \
  --name compute-agent \
  --restart unless-stopped \
  -p 8080:8080 \
  -e AGENT_ID=compute_agent_001 \
  -e AGENT_CAPABILITY=compute \
  langmanus/agent-orchestrator:latest \
  python agent_server.py 8080

# 以此类推...
```

#### 方式二：直接运行 Python（开发测试）

```bash
# 在远程节点上
git clone https://github.com/your-org/langmanus.git
cd langmanus

# 安装依赖
pip install -r requirements.txt

# 启动 Agent
export AGENT_ID=search_agent_001
export TAVILY_API_KEY=your_key
python agent_server.py 8080

# 使用 systemd 或 supervisor 保持运行
```

### Step 3: 配置 Agent 注册表

编辑 `config/agent_registry.json`，填入各个 Agent 的真实地址：

```json
{
  "version": "1.0",
  "agents": [
    {
      "id": "search_agent_001",
      "ip": "192.168.1.101",      // ← 真实的 Agent 节点 IP
      "port": 8080,
      "capability": "search",
      "enabled": true,              // ← 启用此 Agent
      "priority": 10,
      "node_name": "node-01"
    },
    {
      "id": "compute_agent_001",
      "ip": "192.168.1.102",      // ← 另一个节点的 IP
      "port": 8080,
      "capability": "compute",
      "enabled": true,
      "priority": 8,
      "node_name": "node-02"
    }
  ]
}
```

### Step 4: 重启 Web UI 以加载新配置

```bash
docker-compose restart web-ui
```

### Step 5: 验证部署

```bash
# 1. 检查 Web UI 状态
curl http://localhost:8000/health

# 2. 检查各个 Agent 状态
curl http://192.168.1.101:8080/health  # 搜索 Agent
curl http://192.168.1.102:8080/health  # 计算 Agent

# 3. 在 Web UI 中查看 Agent 列表
open http://localhost:8000
```

## 🔧 配置详解

### Agent 注册表配置项

| 字段 | 说明 | 示例 |
|------|------|------|
| `id` | Agent 唯一标识 | `search_agent_001` |
| `ip` | Agent 节点 IP 地址 | `192.168.1.101` 或 `node01.company.com` |
| `port` | Agent 监听端口 | `8080` |
| `capability` | Agent 能力类型 | `search`, `compute`, `nlp` 等 |
| `enabled` | 是否启用 | `true` / `false` |
| `priority` | 调度优先级 (1-10) | `10` (数字越大优先级越高) |
| `node_name` | 节点名称（可选） | `node-01` |
| `tags` | 标签（可选） | `["search", "web"]` |

### 本地开发配置

如果在本地测试，可以使用 `127.0.0.1` 或 `localhost`：

```json
{
  "agents": [
    {
      "id": "search_agent_001",
      "ip": "127.0.0.1",
      "port": 8080,
      "enabled": true
    },
    {
      "id": "compute_agent_001",
      "ip": "127.0.0.1",
      "port": 8081,
      "enabled": true
    }
  ]
}
```

然后在本地启动多个 Agent：

```bash
# Terminal 1
python agent_server.py 8080

# Terminal 2
python agent_server.py 8081
```

## 🌐 网络要求

### 端口开放

确保以下端口在防火墙中开放：

- **Web UI 节点**：8000 (HTTP)
- **各个 Agent 节点**：8080 或自定义端口 (HTTP)

### 网络连通性

- Web UI 必须能够访问所有 Agent 节点的 IP:Port
- 可以使用以下命令测试连通性：

```bash
# 从 Web UI 节点测试
curl http://192.168.1.101:8080/health
telnet 192.168.1.101 8080
```

### 使用域名

支持使用域名代替 IP：

```json
{
  "agents": [
    {
      "id": "search_agent_001",
      "ip": "agent01.company.com",
      "port": 8080
    }
  ]
}
```

## 📊 监控和管理

### 查看 Agent 状态

访问 Web UI：http://localhost:8000

在界面中可以看到：
- 所有 Agent 的在线状态
- 各个 Agent 的能力和描述
- 实时任务分配情况

### 健康检查

```bash
# Web UI 健康检查
curl http://localhost:8000/api/agents

# 单个 Agent 健康检查
curl http://192.168.1.101:8080/health
```

### 动态启用/禁用 Agent

编辑 `config/agent_registry.json`，修改 `enabled` 字段：

```json
{
  "id": "vision_agent_001",
  "enabled": false  // 禁用此 Agent
}
```

重启 Web UI：

```bash
docker-compose restart web-ui
```

## 🔒 安全建议

### 1. 使用 HTTPS

在生产环境中，建议使用 Nginx 反向代理：

```nginx
server {
    listen 443 ssl;
    server_name langmanus.company.com;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
    
    location / {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 2. 使用 VPN 或内网

建议将 Agent 部署在内网或 VPN 中，不暴露到公网。

### 3. API 认证

在 `agent_server.py` 中添加 API Key 认证：

```python
from fastapi import Header, HTTPException

@app.post("/a2a/execute")
async def execute(
    message: A2AMessage,
    x_api_key: str = Header(None)
):
    if x_api_key != os.getenv("AGENT_API_KEY"):
        raise HTTPException(401, "Unauthorized")
    # ... 执行逻辑
```

## 🚀 扩展和优化

### 添加新的 Agent 节点

1. 在新节点上启动 Agent
2. 在 `config/agent_registry.json` 中添加配置
3. 重启 Web UI

### 负载均衡

如果同一种能力有多个 Agent，系统会根据 `priority` 自动选择：

```json
{
  "agents": [
    {
      "id": "search_agent_001",
      "capability": "search",
      "priority": 10
    },
    {
      "id": "search_agent_002",
      "capability": "search",
      "priority": 8  // 备用 Agent
    }
  ]
}
```

### 高可用部署

使用 Kubernetes 部署 Web UI，实现多副本：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: langmanus-web-ui
spec:
  replicas: 3
  selector:
    matchLabels:
      app: langmanus-web-ui
  template:
    metadata:
      labels:
        app: langmanus-web-ui
    spec:
      containers:
      - name: web-ui
        image: langmanus/agent-orchestrator:latest
        ports:
        - containerPort: 8000
```

## 🐛 故障排查

### Agent 无法连接

```bash
# 1. 检查 Agent 是否运行
curl http://192.168.1.101:8080/health

# 2. 检查防火墙
telnet 192.168.1.101 8080

# 3. 检查网络连通性
ping 192.168.1.101

# 4. 查看 Agent 日志
docker logs search-agent
```

### 配置不生效

```bash
# 重启 Web UI 以重新加载配置
docker-compose restart web-ui

# 查看日志确认配置已加载
docker-compose logs web-ui | grep "从配置文件加载"
```

### 性能问题

- 检查 Agent 节点的 CPU/内存使用率
- 调整 `priority` 优先使用高性能节点
- 增加更多 Agent 节点分担负载
