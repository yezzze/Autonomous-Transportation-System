## 🎓 分布式代理调度系统 - 模块化介绍

---

### 1️⃣ **需求解析模块** (Planner Node)

**核心技术**：使用 LLM (qwq-plus) 进行智能任务分解和能力匹配。

**工作流程**：系统首先从 Agent Registry 查询所有可用的智能体及其能力描述，然后将这些信息动态注入到 Prompt 中，引导 LLM 分析用户请求的意图。LLM 会进行推理链思考，识别需要哪些能力（如搜索、计算、NLP），将复杂任务分解为多个独立子任务，并为每个子任务匹配最合适的 Agent ID。最终输出结构化的 JSON 执行计划，包含任务描述、依赖关系和 Agent 分配信息。整个过程采用 Few-Shot 提示工程，确保 LLM 输出符合预定义的 TypeScript 接口格式，便于后续解析和执行。

**代码位置**：distributed_nodes.py - `distributed_planner_node()` 函数

---

### 2️⃣ **智能体调用模块** (Executor Node)

**核心技术**：基于 HTTP REST API 的远程 RPC 调用机制。

**工作流程**：Executor 接收 Planner 生成的执行计划后，按顺序遍历每个任务。对于每个任务，系统会根据 Agent ID 查询其物理地址 (IP:Port)，构建标准化的 HTTP POST 请求，payload 中包含任务描述、上下文信息和前序任务结果。支持超时控制（默认 30 秒）、失败重试机制（最多 3 次）和详细的错误处理。远程 Agent 执行完成后返回 JSON 格式的结果，系统收集并更新执行计划中的任务状态。当前实现包含 Mock 模式，根据不同 Agent 类型（search/nlp/compute/vision/code/web）返回真实的模拟数据，便于开发测试。

**代码位置**：distributed_nodes.py - `distributed_executor_node()` 函数

---

### 3️⃣ **智能体管理模块** (Agent Registry)

**核心技术**：服务注册与发现机制，采用 Mock 实现，可无缝切换到 etcd/Consul/Nacos。

**工作流程**：Agent Registry 维护了所有在线智能体的元数据，包括唯一 ID、IP 地址、端口号、能力标签 (capability)、状态信息和详细描述。系统提供两个核心 API：`query_agents(capability)` 用于按能力过滤查询（如查询所有具备 "search" 能力的 Agent），`get_agent_by_id(id)` 用于获取特定 Agent 的完整信息。当前 Mock 实现预定义了 6 个虚拟 Agent（search/compute/vision/nlp/code/web），分布在 192.168.1.10-15 的 8080 端口。在生产环境中，可替换为分布式注册中心（如 etcd watch 机制），支持 Agent 动态上下线、健康检查和负载信息上报。

**代码位置**：`src/service/agent_registry.py` - `AgentRegistryClient` 类

---

### 4️⃣ **智能体编排模块** (Workflow Orchestration)

**核心技术**：基于 LangGraph 的状态机编排引擎，支持条件跳转和循环控制。

**工作流程**：系统采用有向图 (Directed Graph) 描述工作流，包含 4 个节点：Planner（规划）→ Executor（执行）→ Monitor（监控）→ Reporter（报告）。每个节点是一个纯函数，接收当前状态 (DistributedState) 并返回 Command 对象指示下一步跳转。Executor 采用迭代执行模式，每次处理一个任务后更新 `current_task_index`，通过 Monitor 检查是否所有任务完成，未完成则循环回 Executor，完成后跳转到 Reporter。状态通过 MessagesState 在节点间传递，包含消息历史、执行计划、Agent 缓存等信息。当前实现是线性执行（Sequential），可扩展为 DAG 拓扑排序实现任务并行执行，通过分析任务的 `depends_on` 字段构建依赖图，使用 ThreadPoolExecutor 并发调用独立任务。

**代码位置**：`src/graph/distributed_builder.py` - `build_distributed_graph()` 函数

### 📊 **模块协作关系**

```
┌─────────────────────────────────────────────────────────┐
│                    用户请求输入                          │
└──────────────────┬──────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────────────┐
│  1️⃣ 需求解析 (Planner)                                  │
│  → LLM 推理 + Agent Registry 查询                       │
│  → 输出：JSON 执行计划                                   │
└──────────────────┬──────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────────────┐
│  3️⃣ 智能体管理 (Registry)                               │
│  → 查询 Agent 元数据 (ID → IP:Port)                    │
│  → 支持动态上下线和健康检查                              │
└──────────────────┬──────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────────────┐
│  4️⃣ 智能体编排 (Orchestration)                          │
│  → 迭代执行任务，状态流转控制                            │
│  → Monitor 检查完成度                                    │
└──────────────────┬──────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────────────┐
│  2️⃣ 智能体调用 (Executor)                               │
│  → HTTP POST 远程调用                                    │
│  → 收集结果，更新任务状态                                │
└──────────────────┬──────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────────────┐
│                  最终结果汇总报告                         │
└─────────────────────────────────────────────────────────┘
```

### 🎯 **技术亮点总结**

| 模块       | 核心技术                 | 创新点                          |
| ---------- | ------------------------ | ------------------------------- |
| 需求解析   | LLM + Prompt Engineering | 动态 Agent 信息注入，结构化输出 |
| 智能体调用 | HTTP RPC + 重试机制      | 标准化协议，支持异构 Agent      |
| 智能体管理 | 服务注册与发现           | 可插拔设计，支持分布式注册中心  |
| 智能体编排 | LangGraph 状态机         | 声明式编排，易于扩展并行执行    |

每个模块职责单一、接口清晰，符合微服务架构设计原则。🚀
