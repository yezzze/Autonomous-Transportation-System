# 架构可视化对比

## 📐 系统架构图

### 原始 LangManus 架构

```
┌─────────────────────────────────────────────────────────────┐
│                         用户输入                              │
└────────────────────────┬────────────────────────────────────┘
                         ↓
                  ┌──────────────┐
                  │ Coordinator  │  ← 理解用户意图
                  │  (LLM Call)  │
                  └──────┬───────┘
                         ↓
                  ┌──────────────┐
                  │   Planner    │  ← 生成任务计划
                  │  (LLM Call)  │     输出：steps[]
                  └──────┬───────┘
                         ↓
                  ┌──────────────┐
                  │  Supervisor  │  ← 动态决策路由
                  │ (LLM Router) │
                  └──────┬───────┘
                         ↓
         ┌───────────────┼───────────────┐
         ↓               ↓               ↓
  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
  │ Researcher  │ │    Coder    │ │   Browser   │
  │  (ReAct)    │ │   (ReAct)   │ │   (ReAct)   │
  └──────┬──────┘ └──────┬──────┘ └──────┬──────┘
         │               │               │
         ↓               ↓               ↓
  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
  │ tavily_tool │ │python_repl │ │browser_tool │
  │   (本地)    │ │   (本地)   │ │   (本地)    │
  └─────────────┘ └─────────────┘ └─────────────┘
         │               │               │
         └───────────────┼───────────────┘
                         ↓
                  回到 Supervisor
                         ↓
                  ┌──────────────┐
                  │   Reporter   │  ← 生成最终报告
                  │  (LLM Call)  │
                  └──────┬───────┘
                         ↓
                  ┌──────────────┐
                  │   结束/END   │
                  └──────────────┘
```

**特点**：
- 🔄 动态路由（Supervisor 每次调用 LLM 决策）
- 🔧 本地工具执行
- 📊 多轮交互（Supervisor ⇄ Workers）

### 新架构：分布式 Agent 调度器

```
┌─────────────────────────────────────────────────────────────┐
│                         用户输入                              │
└────────────────────────┬────────────────────────────────────┘
                         ↓
                  ┌──────────────────────┐
                  │  Planner (Enhanced)  │
                  │                      │
                  │  1. 查询 L3 Registry │ ← 🆕 动态 Agent 发现
                  │  2. LLM 生成计划     │
                  │  3. 匹配 Agent IP    │
                  └──────┬───────────────┘
                         │
                         ↓ 输出：execution_plan[]
                         │ [
                         │   {task_id, description, target_ip, port},
                         │   {task_id, description, target_ip, port},
                         │   ...
                         │ ]
                         ↓
                  ┌──────────────────────┐
                  │   Executor (通用)    │
                  │                      │
                  │  for task in plan:   │
                  │    POST http://ip:port/execute │ ← 🆕 远程调用
                  └──────┬───────────────┘
                         │
                         ↓ HTTP Request
         ┌───────────────┼───────────────┐
         ↓               ↓               ↓
  ┌─────────────────────────────────────────────┐
  │         远程 L3 Agent 集群                   │
  │  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
  │  │ Search   │  │ Compute  │  │  Vision  │ │
  │  │ Agent    │  │  Agent   │  │  Agent   │ │
  │  │ :8080    │  │  :8080   │  │  :8080   │ │
  │  └────┬─────┘  └────┬─────┘  └────┬─────┘ │
  │       │             │             │        │
  │  192.168.1.10  192.168.1.11  192.168.1.12 │
  └───────┼─────────────┼─────────────┼────────┘
          │             │             │
          └─────────────┼─────────────┘
                        ↓ HTTP Response
                  ┌──────────────────────┐
                  │      Monitor         │
                  │                      │
                  │  检查: 是否完成？    │ ← 🆕 简化路由
                  │  - 未完成 → Executor │
                  │  - 完成 → Reporter   │
                  └──────┬───────────────┘
                         ↓
                  ┌──────────────┐
                  │   Reporter   │  ← ✅ 保留
                  │  汇总结果     │
                  └──────┬───────┘
                         ↓
                  ┌──────────────┐
                  │   结束/END   │
                  └──────────────┘
```

**特点**：
- 📍 静态路由（预先规划任务）
- 🌐 远程 HTTP 调用
- 🔁 串行执行（可扩展为并行）

## 🔄 工作流序列图

### 原始 LangManus 序列图

```
用户    Coordinator  Planner  Supervisor  Researcher  Coder  Browser  Reporter
 │           │         │         │           │         │       │        │
 ├──请求────→│         │         │           │         │       │        │
 │           ├─澄清───→│         │           │         │       │        │
 │           │         ├─计划───→│           │         │       │        │
 │           │         │         ├─决策─────→│         │       │        │
 │           │         │         │           ├─搜索───→│       │        │
 │           │         │         │←─结果────┤         │       │        │
 │           │         │         ├─决策─────────────→│       │        │
 │           │         │         │                    ├─执行─→│        │
 │           │         │         │←─结果──────────────┤       │        │
 │           │         │         ├─决策─────────────────────→│        │
 │           │         │         │                            ├─浏览─→│
 │           │         │         │←─结果──────────────────────┤        │
 │           │         │         ├─决策──────────────────────────────→│
 │           │         │         │                                     ├─报告→
 │←─最终结果──┴─────────┴─────────┴─────────────────────────────────────┘
```

**Token 消耗**：
- Coordinator: ~1000 tokens
- Planner: ~2000 tokens
- Supervisor (每次): ~500 tokens × N 次
- Workers (每次): ~1500 tokens × N 次
- Reporter: ~2000 tokens

**总计**：约 5000 + (2000 × N) tokens

  ↓

## 🎯 关键差异总结表

| 维度 | 原始 LangManus | 分布式调度器 |
|-----|---------------|------------|
| **路由方式** | 动态（LLM 决策） | 静态（预先规划） |
| **Agent 位置** | 本地 | 远程（HTTP） |
| **Agent 数量** | 固定 4 个 | 动态（查询注册表）|
| **执行模式** | 多轮对话 | 一次规划，顺序执行 |
| **Token 消耗** | O(N) - 随任务数增长 | O(1) - 固定 |
| **扩展性** | 受限于本地资源 | 无限（横向扩展）|
| **容错** | Agent 失败即任务失败 | 支持重试和重新分配 |
| **监控复杂度** | 低（本地调用） | 高（需监控网络）|

## 🔍 详细组件对比

### Planner 对比

| 方面 | 原始 | 新版本 |
|-----|------|--------|
| **输入** | 用户请求 | 用户请求 + L3 Agent 列表 |
| **Prompt 内容** | "可用 Agent: researcher, coder..." | "可用 Agent: \n- search_agent_001 (192.168.1.10)\n- ..." |
| **输出格式** | `{"steps": [...]}` | `{"tasks": [{"assigned_agent_id": "..."}]}` |
| **后处理** | 验证 JSON | 验证 JSON + 映射 IP |
| **依赖** | 无 | `AgentRegistryClient` |

### Executor 对比

| 方面 | 原始 (Researcher) | 新版本 |
|-----|------------------|--------|
| **触发方式** | Supervisor 路由 | 循环执行 |
| **执行逻辑** | `research_agent.invoke()` | `requests.post()` |
| **工具** | tavily_tool | 无（远程）|
| **返回格式** | `{"messages": [...]}` | `{"status": "...", "result": "..."}` |
| **错误处理** | ReAct Agent 内部 | 显式 try-except |

## 🎨 概念模型

### 原始：中心化控制

```
        Supervisor (大脑)
           /  |  \
          /   |   \
    Worker1 Worker2 Worker3
       |      |      |
    Tool1   Tool2  Tool3
```

- **优点**：灵活、智能
- **缺点**：Token 消耗高、扩展受限

---

### 新架构：分布式编排

```
        Planner (总指挥)
           ↓
    Execution Plan (作战计划)
           ↓
    Executor (传令兵)
           ↓
    [远程 Agent 集群]
       Agent1  Agent2  Agent3  ...
```

- **优点**：可扩展、Token 高效
- **缺点**：灵活性降低

---

## 📖 总结

通过这些可视化图表，你可以清晰地看到：

1. **架构演进**：从单体到分布式
2. **控制流变化**：从动态路由到静态规划
3. **数据流变化**：从本地调用到远程 HTTP
4. **部署模式变化**：从单服务到多层架构

这些变化共同实现了从**工具使用型 Agent** 到**分布式调度器**的转型。
