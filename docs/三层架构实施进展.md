> 更新时间：2026-03-06

## 一、架构概览

系统采用 **端-边-云协同的三层架构**，从上到下依次为：

```
┌──────────────────────────────────────────────────────────────┐
│                     应用管理层 (APP)                          │
│  APPM 应用管理器 │ AW 智能体仓库 │ ALRE 执行引擎 │ DISP 呈现  │
├──────────────────────────────────────────────────────────────┤
│                   智能体编排层 (Orchestration)                 │
│  AOE 编排引擎 │ AWM 工作流管理 │ ASD 调度部署                  │
│  ARDC 注册发现 │ RRDC 资源注册                                 │
├──────────────────────────────────────────────────────────────┤
│                   智能体运行层 (Runtime)                       │
│  ALCM 生命周期管理 │ SBOX 执行沙箱 │ COMM 通信中间件           │
│  INTF 资源接口 │ QoS 监控保障                                  │
└──────────────────────────────────────────────────────────────┘
```

跨层支撑：**安全与可信**、**系统监控**、**配置与策略管理**（暂未实现）

## 二、已完成功能

### 2.1 智能体编排层（完成度 ~90%）

#### ✅ AOE 智能体编排引擎
- **文件**：`src/graph/builder.py`、`src/graph/distributed_builder.py`、`src/graph/magentic_builder.py`
- 三种编排模式：
  - `Sequential`（顺序）：SIMPLE 任务，线性执行
  - `Concurrent/Distributed`（分布式）：MEDIUM 任务，Planner→Executor→Monitor→Reporter
  - `Magentic-One`：COMPLEX 任务，带 Progress Ledger 的反馈循环
- 自适应模式选择：`src/graph/adaptive_orchestrator.py`（LLM 评估 + 规则评估双模式）

#### ✅ AWM 智能体工作流管理
- **文件**：`src/graph/distributed_nodes.py`、`src/graph/magentic_nodes.py`
- 任务分解与 Agent 匹配、执行计划生成、失败重试、重规划（最多 2 次）
- Progress Ledger 5 维度分析（`src/graph/progress_ledger.py`）：
  - `is_request_satisfied`、`is_in_loop`、`is_progress_being_made`、`next_speaker`、`instruction_or_question`

#### ✅ ARDC 智能体注册与发现中心
- **文件**：`src/service/agent_registry.py`
- 支持 JSON 配置文件加载（`config/agent_registry.json`）
- 精确匹配 + HNSW 向量检索（Agent 数量 > 100 时自动启用）
- 6 个预定义 Mock Agent：search / compute / vision / nlp / code / web

#### ✅ ASD 智能体调度与部署（新增）
- **文件**：`src/service/agent_scheduler.py`
- `deploy_agent(image_id, agent_id, node_id, cpu_cores, memory_mb)` → 创建部署记录，注册 ARDC
- `shutdown_agent(agent_id, force)` → 关闭实例，注销 ARDC
- `health_check(agent_id)` / `get_running_agents()` / `list_deployments_by_agent()`
- 当前：Mock 级别（记录意图，不执行真实容器操作）

#### ✅ RRDC 资源注册与发现中心（新增）
- **文件**：`src/service/resource_registry.py`
- `ResourceInfo`：node_id / node_type / ip / cpu_total+available / mem_total+available / gpu_count / tags / status
- `query_available_resources(min_cpu, min_mem_mb, node_type, tags)` → 返回满足条件的节点列表
- `allocate(node_id, cpu, mem)` / `release(node_id, cpu, mem)` → 资源动态管理
- 3 个预定义节点（与 agent_registry.json IP 对应）

#### ✅ 跨主体工作流骨架（新增）
- **文件**：`src/graph/distributed_nodes.py`
- `dispatch_subtask_to_remote_aoe(subtask, remote_aoe_url)` → 发送子任务到远端 AOE
- `identify_cross_host_tasks(execution_plan, available_agents)` → 识别需跨主体路由的任务
- `DistributedState` 新增字段：`cross_host_sessions: Dict[str, str]`、`session_timeout_seconds: int`

#### ✅ COMM 跨 Agent 通信中间件
- **文件**：`src/protocols/a2a_protocol.py`、`src/service/a2a_client.py`
- A2A 协议：`A2AMessage`、`A2ATaskRequest`、`A2ATaskResponse`、`A2ACapabilityDeclaration`、`A2AProgressNotification`
- 支持同步调用、异步流式执行、进度通知

### 2.2 应用管理层（新建，完成度 ~85%）

所有文件位于 `src/app/` 目录：

#### ✅ 数据模型（`src/app/models.py`）
| 模型 | 用途 |
|------|------|
| `AgentImage` | AW 存储单元：image_id / name / version / capability / exposed_external |
| `GuidanceFile` | ALRE 存储的编排指导文件：task_description / orchestration_mode / agents_required / constraints |
| `AppInfo` | APPM 管理实体：app_id / name / status / image_ids / workflow_handle / app_interface_url |
| `AppStatus` | `idle` \| `starting` \| `running` \| `stopping` \| `stopped` \| `error` |

#### ✅ AW 智能体仓库（`src/app/agent_warehouse.py`）
- `install_agent(image, expose_external)` → 本地存储 + 向 ARDC 注册
- `uninstall_agent(image_id)` → 从 ARDC 注销 + 删除本地记录
- JSON 持久化：`config/agent_warehouse.json`
- 查询接口：`get_image()` / `list_images()` / `find_by_capability()`

#### ✅ ALRE 应用逻辑执行引擎（`src/app/app_logic_engine.py`）
- `install_app_logic(guidance_file)` / `uninstall_app_logic(app_id)` → 指导文件 CRUD
- `start_app(app_id)` → 解析指导文件 → `asyncio.create_task` 后台运行 `run_distributed_workflow()`
- `stop_app(app_id)` → `task.cancel()` + 等待取消完成
- `is_running(app_id)` / `get_workflow_handle(app_id)` → 查询运行状态

#### ✅ APPM 应用管理器（`src/app/app_manager.py`）
- 聚合 AW + ALRE，对外提供统一接口：
  - `install(name, guidance_file, images, expose_external)` → 安装
  - `uninstall(app_id)` → 卸载
  - `async start(app_id)` → 启动（状态：idle→starting→running）
  - `async stop(app_id)` → 停止（状态：running→stopping→stopped）
  - `list_apps()` / `list_running_apps()` / `get_app(app_id)` → 查询

#### ✅ DISP 交互与呈现（`src/app/display.py`）
- `get_running_app_list()` → 运行中应用列表（供 UI 展示）
- `get_all_app_list()` → 所有应用列表
- `get_app_interface(app_id)` → 应用接口信息（含 input_schema 占位）

### 2.3 智能体运行层（新建，完成度 ~75%）

所有文件位于 `src/runtime/` 目录：

#### ✅ 数据模型（`src/runtime/models.py`）
| 模型 | 关键字段 |
|------|---------|
| `AgentInstance` | instance_id / agent_id / image_id / status / ref_count / subscribed_workflows / resource_config |
| `ResourceConfig` | cpu_cores / memory_mb / node_id / gpu_count |
| `QoSMetrics` | total_calls / success_count / failure_count / total_latency_ms / min/max_latency_ms |

#### ✅ ALCM 生命周期管理（`src/runtime/lifecycle_manager.py`）
- `deploy_agent(agent_id, image_id, resource_config)` → RRDC 申请资源 → 创建实例 → 调 ASD 部署
- `subscribe(instance_id, workflow_id)` → 引用计数 +1（对应接口文档：AWM→ALCM 订阅）
- `unsubscribe(instance_id, workflow_id)` → 引用计数 -1，**归零时自动关闭**（`_idle_shutdown`）
- `shutdown_agent(instance_id, force)` → 停容器 → 释放 RRDC 资源 → 从 ARDC 注销
- `list_instances()` / `list_running_instances()` / `get_instance()` / `shutdown_all_by_agent()`

#### ✅ INTF 资源访问接口（`src/runtime/resource_interface.py`）
- 抽象基类 `ResourceInterface`（ABC）：`interface_type` / `async access(request)` / `get_status()`
- 4 种 Mock 实现：`ComputeResourceInterface` / `CommunicationInterface` / `SensorInterface` / `ActuatorInterface`
- `ResourceInterfaceRegistry`：按类型注册、获取、统一调用 `async access(type, request)`

#### ✅ QoS 监控与保障（`src/runtime/qos_monitor.py`）
- `record_call(agent_id, latency_ms, success)` → 更新统计指标
- `get_metrics(agent_id)` / `get_all_metrics()` → 指标查询（供资源 Agent 读取）
- `check_threshold(agent_id)` → 告警检查规则：
  - 平均延迟 > 5000ms → 告警
  - 调用次数 ≥ 5 且成功率 < 80% → 告警
- `get_alert_agents()` / `get_summary()` / `reset_metrics()`

## 四、关键设计决策

### 4.1 实现粒度：骨架优先
- **决策**：本阶段以接口定义 + 数据模型 + 关键逻辑框架为目标，不过度工程化
- **原因**：快速覆盖三层架构全貌，优先验证接口契约，具体实现可迭代替换
- **影响**：ASD 部署为 Mock，INTF 资源访问为 Mock，跨主体 HTTP 调用为 Mock

### 4.2 执行沙箱：跳过本期
- **决策**：SBOX 不在本期实现，由现有 L1 工具（`src/tools/`）提供能力
- **原因**：容器级隔离需引入 Docker SDK，复杂度高、与核心架构解耦
- **扩展点**：`src/runtime/` 已预留 `resource_interface.py`，可在其中添加 SBOX 封装

### 4.3 AW 持久化：JSON 文件
- **决策**：镜像仓库使用 `config/agent_warehouse.json` 持久化
- **原因**：与 `config/agent_registry.json` 保持一致的简单风格，避免引入数据库依赖
- **升级路径**：替换 `_load_from_json()` / `_save_to_json()` 为数据库调用即可

### 4.4 引用计数归零自动关闭
- **决策**：ALCM `unsubscribe()` 引用计数归零时调用 `_idle_shutdown()` 自动关闭实例
- **原因**：契合接口文档设计（运行层接口 §2.3 中"引用为0时，关闭智能体"）
- **注意**：`shutdown_agent(force=True)` 可绕过引用计数强制关闭

### 4.5 跨主体路由：本节点 IP 白名单判断
- **决策**：`identify_cross_host_tasks()` 通过 `LOCAL_NODE_IDS = {"localhost", "host.docker.internal", "127.0.0.1"}` 判断是否需要跨主体
- **原因**：简单轻量，适合当前 Mock 阶段
- **升级路径**：改为从 RRDC 查询本节点 node_id，与 Agent IP 精确对比

### 4.6 会话超时机制
- **决策**：`DistributedState.session_timeout_seconds` 字段 + `cross_host_sessions` 映射
- **原因**：接口文档明确要求"由其他主体创建的工作流，需设置会话超时"
- **当前状态**：字段已定义，超时检查逻辑待在 AWM 中实现（P1）

### 4.7 LLM 三模型体系（保持不变）
- `REASONING_MODEL`（如 qwq-plus）：规划、复杂分析，仅支持 streaming
- `BASIC_MODEL`（如 qwen-flash）：快速决策、简单任务
- `VL_MODEL`（如 qwen2.5-vl-72b）：视觉/图像任务
