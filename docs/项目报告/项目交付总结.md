## 🏗️ 架构设计

### Layer 2 定位

```
┌─────────────────────────────────────────────┐
│           用户/应用层（Layer 1）              │
│        Slack Bot, Web API, CLI, ...         │
└──────────────────┬──────────────────────────┘
                   │
                   ↓
┌─────────────────────────────────────────────┐
│      分布式调度器（Layer 2）★ 本系统         │
│                                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ Planner  │→ │ Executor │→ │ Reporter │  │
│  └──────────┘  └──────────┘  └──────────┘  │
│       ↑             ↓                        │
│       │      HTTP POST 远程调用              │
│       │             ↓                        │
│  Agent Registry (etcd/Consul)               │
└──────────────────┬──────────────────────────┘
                   │
                   ↓
┌─────────────────────────────────────────────┐
│         执行代理层（Layer 3）                 │
│                                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ Search   │  │ Compute  │  │ Vision   │  │
│  │ Agent    │  │ Agent    │  │ Agent    │  │
│  └──────────┘  └──────────┘  └──────────┘  │
│                                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ NLP      │  │ Code     │  │ Web      │  │
│  │ Agent    │  │ Agent    │  │ Agent    │  │
│  └──────────┘  └──────────┘  └──────────┘  │
└─────────────────────────────────────────────┘
```

### 工作流程

```
1. 用户输入 → "搜索 DeepSeek R1 最新消息，并总结要点"

2. Planner 节点：
   - 查询 Agent Registry → [search_001, nlp_001, ...]
   - 调用 LLM（qwq-plus）生成计划
   - 输出：
     {
       "tasks": [
         {
           "task_id": "task_001",
           "agent_id": "search_001",
           "description": "搜索 DeepSeek R1..."
         },
         {
           "task_id": "task_002",
           "agent_id": "nlp_001",
           "description": "总结关键信息...",
           "depends_on": ["task_001"]
         }
       ]
     }

3. Executor 节点：
   - 按顺序执行任务
   - POST http://192.168.1.10:8080/execute {"task": "..."}
   - 收集结果：{"status": "success", "result": "..."}

4. Monitor 节点：
   - 检查所有任务是否完成
   - 判断成功/失败

5. Reporter 节点：
   - 调用 LLM（qwen-max-latest）生成报告
   - 汇总统计信息和结果
```

## 🎯 核心特性

### 1. 完全去中心化的 Agent 调度

- ✅ **不再依赖本地 Tool-Calling**
- ✅ **通过 HTTP 调用远程 Agent**
- ✅ **支持动态 Agent 注册和发现**

### 2. 静态编排 + 动态选择

- **静态编排**：Planner → Executor → Monitor → Reporter（固定流程）
- **动态选择**：运行时从 Registry 查询可用 Agent
- **可扩展性**：可改为 DAG 并行执行

### 3. 三级 Agent 选择机制

```
Level 1: Registry Query
   ↓
   基于 capability 过滤（search/compute/vision/nlp/code/web）
   
Level 2: LLM Matching
   ↓
   Planner 使用 LLM 根据任务描述选择最佳 Agent
   
Level 3: Load Balancing (可选)
   ↓
   根据负载、延迟、成功率等动态调度
```

### 4. Mock 模式开发

- **快速测试**：无需部署真实 Agent
- **6个预定义 Agent**：search/compute/vision/nlp/code/web
- **模拟响应**：返回示例结果
- **易于切换**：修改 `MOCK_REMOTE_EXECUTION` 标志

## 🔧 技术栈

### 核心框架

- **LangGraph 0.6.11**：工作流编排
- **LangChain 0.3.x**：LLM 抽象层
- **StateGraph + Command**：状态机 + 控制流

### LLM 服务

- **阿里云 DashScope**（OpenAI 兼容接口）

  - `qwen-max-latest`：基础模型（Reporter）
  - `qwen2.5-vl-72b-instruct`：视觉模型（备用）

### 通信协议

- **HTTP REST API**：Agent 远程调用
- **JSON**：数据交换格式

### 开发工具

- **Python 3.11**：语言环境

|-----|------------|---------------------------|
| **架构** | 单机多 Agent | 分布式多 Agent |

| **扩展性** | 受限于单机 | 水平扩展（分布式） |

| **部署** | 单进程 | 多服务部署 |

## 📝 已知限制和改进方向

### 当前限制

1. **线性执行**：任务按顺序执行，未实现并行（可扩展为 DAG）
2. **Mock Registry**：使用硬编码的 6 个 Agent（需接入真实注册中心）
3. **Mock HTTP 调用**：Executor 返回模拟结果（需部署真实 Agent）
4. **简单监控**：仅检查任务状态，无负载均衡和容错

### 改进方向

1. **并行执行**：改造 Executor 支持 DAG 拓扑排序
2. **Agent Registry**：接入 etcd/Consul/Nacos
3. **负载均衡**：添加基于延迟/负载的动态调度
4. **容错机制**：超时重试、熔断降级、故障隔离
5. **监控可观测**：Prometheus 指标、Jaeger 追踪、ELK 日志
6. **安全认证**：JWT Token、mTLS、API Gateway
