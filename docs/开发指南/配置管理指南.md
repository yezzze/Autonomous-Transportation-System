# 配置管理指南

## 📋 概述

LangManus 采用**完全外部化配置**设计，所有配置文件都可以在容器外部修改，无需重新构建镜像。

## 🗂️ 配置文件清单

| 配置文件 | 路径 | 用途 | 修改后操作 |
|---------|------|------|-----------|
| `.env` | 项目根目录 | 所有环境变量（API密钥、模型配置等） | 重启容器 |
| `agent_registry.json` | `config/agent_registry.json` | Agent节点注册表（IP、端口、能力） | 重启容器 |
| 未来扩展... | `config/*.yaml` | 其他配置文件（如工具配置、路由规则） | 重启容器 |

## 🎯 配置文件详解

### 1️⃣ `.env` - 环境变量配置

**位置**：项目根目录 `.env`

**作用**：集中管理所有环境变量，包括：
- LLM API 密钥和端点
- 第三方服务密钥（Tavily等）
- 系统开关（LLM模拟器、调试模式）
- 应用环境配置

**修改方式**：
```bash
# 方式一：直接编辑
vim .env

# 方式二：使用 sed 批量替换
sed -i 's/your_old_key/your_new_key/g' .env

# 方式三：使用环境变量覆盖（不修改文件）
export REASONING_API_KEY=new_key
docker-compose up -d
```

**生效方式**：
```bash
# 修改后重启容器
docker-compose restart web-ui

# 或者重新启动
docker-compose down && docker-compose up -d
```

**配置示例**：
```bash
# ===== LLM 配置 =====
REASONING_API_KEY=sk-your-key-here
REASONING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
REASONING_MODEL=qwen-flash

BASIC_API_KEY=sk-your-key-here
BASIC_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
BASIC_MODEL=qwen-flash

# ===== 应用配置 =====
USE_LLM_SIMULATOR=true
LLM_SIMULATOR_MODEL=basic

# ===== 第三方服务 =====
TAVILY_API_KEY=tvly-your-key-here
```

### 2️⃣ `config/agent_registry.json` - Agent 注册表

**位置**：`config/agent_registry.json`

**作用**：定义分布式 Agent 的部署拓扑
- Agent ID 和能力映射
- IP 地址和端口配置
- 优先级和启用状态

**修改方式**：
```bash
# 直接编辑
vim config/agent_registry.json

# 使用 jq 修改（推荐）
jq '.agents[0].ip = "192.168.1.100"' config/agent_registry.json > tmp.json && mv tmp.json config/agent_registry.json
```

**生效方式**：
```bash
# 修改后重启 Web UI
docker-compose restart web-ui
```

**配置示例**：
```json
{
  "version": "1.0",
  "agents": [
    {
      "id": "search_agent_001",
      "ip": "127.0.0.1",
      "port": 8080,
      "capability": "search",
      "enabled": true,
      "priority": 10
    }
  ]
}
```

## 🔧 配置文件在 Docker 中的工作原理

### Volume 挂载方式

docker-compose.yml 配置：
```yaml
services:
  web-ui:
    volumes:
      - ./config:/app/config          # 挂载配置目录
      - ./logs:/app/logs              # 挂载日志目录
      - ./data:/app/data              # 挂载数据目录
      - ./.env:/app/.env              # 挂载环境变量文件
    env_file:
      - .env                          # 从外部 .env 加载环境变量
```

### 配置加载优先级

1. **容器启动时**：读取宿主机的 `.env` 和 `config/` 文件
2. **运行时**：容器内的应用直接访问挂载的文件
3. **修改后**：重启容器即可生效，无需重新构建镜像

## 📝 最佳实践

### ✅ 推荐做法

1. **版本控制**：
   ```bash
   # 提交模板文件，不提交真实配置
   git add .env.example
   git add config/agent_registry.json.example
   
   # 实际使用的配置不提交
   echo ".env" >> .gitignore
   ```

2. **配置备份**：
   ```bash
   # 备份当前配置
   cp .env .env.backup.$(date +%Y%m%d)
   cp config/agent_registry.json config/agent_registry.json.backup.$(date +%Y%m%d)
   ```

3. **多环境管理**：
   ```bash
   # 开发环境
   cp .env.dev .env
   docker-compose up -d
   
   # 生产环境
   cp .env.prod .env
   docker-compose up -d
   ```

4. **配置验证**：
   ```bash
   # 启动前验证配置
   python -c "import json; json.load(open('config/agent_registry.json'))"
   python -c "from dotenv import load_dotenv; load_dotenv(); import os; print('OK' if os.getenv('REASONING_API_KEY') else 'Missing keys')"
   ```

### ❌ 避免的做法

1. ❌ **硬编码配置到镜像**：修改需要重新构建镜像
2. ❌ **在 Dockerfile 中 COPY .env**：配置无法外部修改
3. ❌ **在 docker-compose.yml 中硬编码环境变量**：修改需要编辑 YAML 文件
4. ❌ **不备份直接修改**：误操作无法恢复

## 🚀 快速配置流程

### 首次部署

```bash
# 1. 复制模板文件
cp .env.example .env

# 2. 编辑配置文件
vim .env                              # 填入真实的 API Key
vim config/agent_registry.json        # 配置 Agent 节点 IP

# 3. 启动服务
docker-compose up -d

# 4. 验证配置
docker-compose logs web-ui | grep "成功加载"
```

### 修改配置

```bash
# 1. 编辑配置
vim .env                              # 修改 API Key 或模型

# 2. 重启容器
docker-compose restart web-ui

# 3. 验证生效
docker-compose logs web-ui -f
```

### 添加新 Agent

```bash
# 1. 编辑注册表
vim config/agent_registry.json
# 添加新的 Agent 条目

# 2. 重启 Web UI
docker-compose restart web-ui

# 3. 在目标节点启动 Agent
ssh user@192.168.1.102
python agent_server.py 8080
```

## 🔍 故障排查

### 配置未生效

```bash
# 检查 volume 挂载
docker inspect langmanus-web-ui | grep -A 10 "Mounts"

# 检查容器内配置文件
docker exec langmanus-web-ui cat /app/.env
docker exec langmanus-web-ui cat /app/config/agent_registry.json

# 检查环境变量
docker exec langmanus-web-ui env | grep API_KEY
```

### 配置文件权限问题

```bash
# 确保宿主机文件可读
chmod 644 .env
chmod 644 config/agent_registry.json

# 确保目录可访问
chmod 755 config/
```

```python

import watchdog.observers
# ... 实现配置热重载逻辑
```

## 🎉 总结

通过 **Volume 挂载 + env_file** 的方式，LangManus 实现了：

✅ **所有配置文件外部化**：`.env`、`agent_registry.json`、未来的其他配置文件  
✅ **修改无需重新构建镜像**：只需重启容器即可  
✅ **版本控制友好**：模板文件入库，真实配置不入库  
✅ **多环境部署简单**：切换 `.env` 文件即可  
✅ **配置集中管理**：所有配置在宿主机上统一维护  

现在你可以在宿主机上随意修改配置，重启容器即可生效，真正实现了**一次构建，到处运行**！
