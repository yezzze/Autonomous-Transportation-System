## 🌐 启用 A2A Agent 通信

### 创建简单的 A2A Agent 服务

```python
# agent_server.py - 简单的搜索 Agent 示例

from fastapi import FastAPI
from pydantic import BaseModel
import requests

app = FastAPI()

class A2AMessage(BaseModel):
    message_id: str
    sender_id: str
    receiver_id: str
    message_type: str
    payload: dict

@app.post("/a2a/execute")
async def execute_task(message: A2AMessage):
    """处理 A2A 任务请求"""
    
    task = message.payload
    task_description = task.get("task_description", "")
    
    # 执行真实的搜索
    if "搜索" in task_description or "search" in task_description:
        query = task_description.replace("搜索", "").strip()
        
        # 调用真实的搜索 API
        result = f"搜索结果: {query}\n\n[真实的搜索结果会在这里]"
        
        return A2AMessage(
            message_id=message.message_id,
            sender_id=message.receiver_id,
            receiver_id=message.sender_id,
            message_type="response",
            payload={
                "task_id": task["task_id"],
                "status": "success",
                "result": result
            }
        )
    
    # 其他任务类型
    return A2AMessage(
        message_id=message.message_id,
        sender_id=message.receiver_id,
        receiver_id=message.sender_id,
        message_type="response",
        payload={
            "task_id": task["task_id"],
            "status": "error",
            "error_message": "不支持的任务类型"
        }
    )

@app.get("/health")
async def health_check():
    """健康检查"""
    return {"status": "online", "load": 0.2, "active_tasks": 0}

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="192.168.1.10", port=8080)
```

### 问题 1: MCP 连接失败

```
❌ ERROR: [Errno 2] No such file or directory: 'npx'
```

**解决方案：**
```bash
# macOS
brew install node

# Ubuntu
sudo apt install nodejs npm

# 验证安装
node --version
npx --version
```

### 问题 2: A2A 连接失败

```
❌ ERROR: 无法连接到远程 Agent 192.168.1.10:8080
```

**解决方案：**
1. 确认 Agent 服务正在运行
2. 检查 IP 和端口是否正确
3. 测试连接：`curl http://192.168.1.10:8080/health`

### 问题 3: LLM 模拟器也失败

```
❌ ERROR: LLM 模拟器失败
```

**解决方案：**
1. 检查 API Key 配置
2. 确认网络连接正常
3. 查看 `src/agents/llm.py` 配置

## 💬 常见问题

**Q: 为什么我的任务总是用 LLM 模拟器？**  
A: 因为 MCP 服务器和 A2A Agent 都未配置。这是正常的降级行为。

**Q: MCP 和 A2A 有什么区别？**  
A: MCP 用于调用明确的工具（如搜索、文件操作），A2A 用于 Agent 间通信（需要推理和决策）。

**Q: 如何禁用降级机制？**  
A: 设置 `export USE_LLM_SIMULATOR=false`，这样失败时会直接报错而不是降级。

**Q: 系统支持并发执行吗？**  
A: 支持。当任务复杂度为 COMPLEX 时，系统会自动使用 Magentic-One 模式并发执行。

**Q: 如何查看详细的执行过程？**  
A: 设置 `export LOG_LEVEL=DEBUG`，会输出所有协议选择和执行细节。
