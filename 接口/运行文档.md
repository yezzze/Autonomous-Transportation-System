## 1. 环境准备

### 1.1 Python 版本

需要 Python **3.11+**（项目实测 3.11.x）。

```bash
python --version   # 应 >= 3.11
```

### 1.2 安装依赖

推荐使用 `uv`（更快）：

```bash
# 方式一：uv（推荐）
uv sync

# 方式二：pip
pip install -r requirements.txt

# 或开发模式安装（含 dev 依赖）
pip install -e ".[dev]"
```

### 1.3 安装 MCP 服务器（可选，提升搜索/浏览能力）

```bash
# 自动安装脚本
./install_mcp_servers.sh

# 或手动安装（需要 Node.js）
npm install -g @modelcontextprotocol/server-filesystem
npm install -g @modelcontextprotocol/server-brave-search
npm install -g @modelcontextprotocol/server-puppeteer
```

## 2. 配置说明

### 2.1 创建 `.env` 文件

```bash
cp .env.example .env   # 如有示例文件
# 或手动创建
```

### 2.2 环境变量参考

| 变量名 | 说明 | 示例 / 默认值 |
|--------|------|--------------|
| `REASONING_MODEL` | 推理模型（任务规划用） | `o1-mini` |
| `REASONING_BASE_URL` | 推理模型 API 地址 | `https://api.openai.com/v1` |
| `REASONING_API_KEY` | 推理模型 API Key | `sk-...` |
| `BASIC_MODEL` | 基础模型（快速决策用） | `gpt-4o` |
| `BASIC_BASE_URL` | 基础模型 API 地址 | `https://api.openai.com/v1` |
| `BASIC_API_KEY` | 基础模型 API Key | `sk-...` |
| `VL_MODEL` | 视觉语言模型 | `gpt-4o` |
| `VL_BASE_URL` | 视觉模型 API 地址 | — |
| `VL_API_KEY` | 视觉模型 API Key | — |
| `USE_LLM_SIMULATOR` | 是否启用 LLM 模拟器（无实际工具时兜底执行） | `true` |
| `LLM_SIMULATOR_MODEL` | 模拟器使用的模型 | `basic`（可选 `reasoning`） |
| `TAVILY_API_KEY` | Tavily 搜索 API Key（agent_server 真实搜索用） | — |
| `BRAVE_API_KEY` | Brave 搜索 API Key（MCP 搜索用） | — |
| `PEER_AOE_URLS` | 分布式模式下的 peer 节点地址列表（逗号分隔） | `http://192.168.1.10:9000,http://192.168.1.20:9000` |
| `REMOTE_AOE_PORT` | 跨主体分发时目标节点的 agent_server 端口 | `9000` |
| `CHROME_INSTANCE_PATH` | Chrome 可执行文件路径（浏览器工具用） | — |
| `AGENT_REGISTRY_CONFIG` | Agent 注册表配置文件路径 | `config/agent_registry.json` |

## 3. 单机模式启动

### 3.1 仅 API 服务（最简启动）

启动 FastAPI 主服务，监听 **8000** 端口：

```bash
# 方式一：直接运行
python server.py

# 方式二：make 命令
make serve

# 方式三：uvicorn 直接启动（可指定参数）
uvicorn src.api.app:app --host 0.0.0.0 --port 8000 --reload
```

启动后访问：
- Swagger UI：`http://localhost:8000/docs`
- Web UI：`http://localhost:8000/ui`

### 3.2 Web UI 可视化监控（推荐）

Web UI 服务包含实时日志、任务进度看板，监听 **8001** 端口：

```bash
python web_ui.py
```

访问：`http://localhost:8001`

### 3.3 Agent 节点服务

每个 Agent 节点独立监听一个端口，提供 A2A 执行能力（可以启动多个）：

```bash
# 节点 1：搜索 Agent（端口 9000）
python agent_server.py 9000

# 节点 2：计算 Agent（端口 9001）
python agent_server.py 9001
```

> `agent_server.py` 默认端口为 `9000`，若不传参则使用默认值。

### 3.4 CLI 任务提交

不启动任何服务，直接在命令行运行工作流：

```bash
# 单条任务（自动选择编排模式）
python distributed_main.py "搜索特斯拉最新股价"

# 复杂任务（触发 Magentic-One 模式）
python distributed_main.py "写一份详细的 AI 技术发展报告，包括趋势分析、市场调研和技术评估"

# 交互式输入
python distributed_main.py
```

## 4. 分布式多节点启动

### 4.1 架构说明

```
节点 A（D_AOE 主编排节点）         节点 B（E_AOE 从节点）
┌─────────────────────────┐        ┌─────────────────────────┐
│  python server.py        │        │  python agent_server.py  │
│  端口: 8000              │        │  端口: 9000              │
│  PEER_AOE_URLS=节点B地址 │<──────>│  PEER_AOE_URLS=节点A地址 │
└─────────────────────────┘        └─────────────────────────┘
```

### 4.2 节点 A 启动（主编排节点）

```bash
# .env 中配置 peer 节点地址
export PEER_AOE_URLS="http://192.168.1.20:9000"
export REMOTE_AOE_PORT="9000"

python server.py           # 主 API 服务，端口 8000
python agent_server.py 9000  # 本地 Agent 节点，同时接收远端子任务
```

### 4.3 节点 B 启动（从节点）

```bash
export PEER_AOE_URLS="http://192.168.1.10:9000"
export REMOTE_AOE_PORT="9000"

python agent_server.py 9000
```

### 4.4 Gossip 网络验证

节点启动后 30 秒内会自动 gossip 同步，可手动触发检查：

```bash
# 查看节点 A 的 Agent 列表（应包含节点 B 的 Agent）
curl http://192.168.1.10:8000/api/agents/instances | python -m json.tool

# 手动推送 gossip
curl -X POST http://192.168.1.20:9000/registry/sync \
  -H "Content-Type: application/json" \
  -d '{"source_url": "http://192.168.1.10:9000", "agents": []}'
```

### 4.5 Agent 注册表配置

为了让 D_AOE 知道哪些任务应路由到哪个节点，编辑 `config/agent_registry.json`：

```json
{
  "agents": [
    {
      "id": "search_agent_remote_001",
      "ip": "192.168.1.20",
      "port": 9000,
      "capability": "search",
      "status": "online",
      "description": "远端搜索 Agent",
      "enabled": true
    }
  ]
}
```

## 5. 各入口说明

| 入口文件 | 用途 | 默认端口 | 备注 |
|----------|------|----------|------|
| `server.py` | FastAPI 主服务 + Web UI | 8000 | 生产推荐入口 |
| `web_ui.py` | 可视化监控服务 | 8001 | 含 WebSocket 实时推送 |
| `agent_server.py [port]` | Agent 节点服务（A2A + 跨主体编排端点） | 9000 | 可多实例启动 |
| `distributed_main.py` | CLI 工作流入口 | — | 直接运行，不需要服务 |
| `main.py` | 原始单机 LangGraph 入口 | — | 不启用分布式功能 |

## 6. API 接口速查

所有接口基础路径：`http://localhost:8000`

### 6.1 应用管理（`/api/apps`）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/apps/` | 获取所有应用列表 |
| `GET` | `/api/apps/running` | 获取运行中的应用列表 |
| `GET` | `/api/apps/{app_id}` | 获取单个应用详情 |
| `POST` | `/api/apps/install` | 安装应用 |
| `DELETE` | `/api/apps/{app_id}/uninstall` | 卸载应用 |
| `POST` | `/api/apps/{app_id}/start` | 启动应用 |
| `POST` | `/api/apps/{app_id}/stop` | 停止应用 |
| `PATCH` | `/api/apps/{app_id}` | 更新应用（含 Skills.md 编辑） |
| `POST` | `/api/apps/{app_id}/interface` | 向应用发送查询（对话） |
| `GET` | `/api/apps/{app_id}/interface` | 获取应用接口说明 |

**示例：安装并启动应用**

```bash
# 安装
curl -X POST http://localhost:8000/api/apps/install \
  -H "Content-Type: application/json" \
  -d '{"name": "我的 AI 助手", "description": "搜索+分析", "skills_content": "# 搜索助手\n能力：网络搜索"}'

# 启动（替换 app_id 为安装返回的 ID）
curl -X POST http://localhost:8000/api/apps/app_abc123/start

# 对话
curl -X POST http://localhost:8000/api/apps/app_abc123/interface \
  -H "Content-Type: application/json" \
  -d '{"query": "帮我搜索今天的 AI 新闻"}'

# 停止
curl -X POST http://localhost:8000/api/apps/app_abc123/stop
```

## 8. 常见问题

### Q1：启动报 `ImportError: cannot import name 'browser_tool'`

已知的循环导入问题，出现在 `tests/integration/test_bash_tool.py`。  
**解决**：运行测试时加 `--ignore=tests/integration/test_bash_tool.py` 跳过。  
主服务 `server.py` 不受影响。

### Q2：任务执行显示 `⚠️ MCP 连接失败，降级到 A2A`

MCP 服务器（Node.js）未安装或未启动。  
**解决**：执行 `./install_mcp_servers.sh`，或设置 `USE_LLM_SIMULATOR=true` 使用 LLM 兜底。

### Q3：跨主体分发一直超时

1. 检查目标节点 `agent_server.py` 是否已启动：`curl http://<ip>:<port>/health`
2. 检查 `PEER_AOE_URLS` 和 `REMOTE_AOE_PORT` 配置是否正确
3. 检查防火墙是否放通目标端口
4. 查看主节点日志中的 `[跨主体]` 前缀日志

### Q4：Gossip 同步后看不到 peer 节点的 Agent

1. 确认双方 `PEER_AOE_URLS` 指向对方
2. Gossip 周期为 30s，稍等片刻或手动触发 `POST /registry/sync`
3. 确认 `config/agent_registry.json` 中对方 Agent 的 `enabled` 为 `true`

### Q5：qwq-plus 等推理模型报 streaming 错误

`qwq-plus`、`o1-mini` 等模型只支持流式调用，项目已在 `src/agents/llm.py` 中自动处理。  
若仍报错，检查 `REASONING_BASE_URL` 是否为支持流式的端点地址。

### Q6：如何查看实时任务执行日志？

- 启动 `python web_ui.py`，浏览器打开 `http://localhost:8001`
- 或直接在终端运行 `python distributed_main.py`，走 CLI 模式，日志输出到 stdout

### Q7：如何在 Docker 中运行？

参考 [接口/Docker部署指南.md（docs/Docker部署指南.md）](../docs/Docker部署指南.md)，或直接：

```bash
# 启动所有服务（含主节点 + Agent 节点）
docker compose up -d

# 开发模式（含热重载）
docker compose -f docker-compose.dev.yml up
```
