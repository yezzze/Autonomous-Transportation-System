# 智能体编排层接口流程 v2

> 本版本在原“智能体编排层接口流程 v1”基础上新增 **MC：记忆中心（Memory Center）**。
> MC 不是普通业务智能体，而是编排层控制面组件，负责记忆抽取、记忆包生成、沙箱挂载、远端委派记忆、执行后记忆回收与本地写回。

---

## 0. 核心设计原则

### 0.1 每个设备都是独立本体

系统中的每个设备都可视为一个独立客户端：

```text
设备 A = 一个独立客户端 / 本体 A
设备 B = 一个独立客户端 / 本体 B
```

每个设备拥有：

```text
1. 本地应用管理层 APP
2. 本地智能体编排层 Orchestration
3. 本地智能体运行层 Runtime
4. 本地记忆中心 MC
5. 本地记忆库 Memory Store
```

设备之间可以互相调用能力，但默认不共享本体私有记忆。

---

### 0.2 Agent 沙箱只能访问专属记忆目录

Agent 由 K8s 沙箱调度，不同 Agent 实例、不同 Workflow、不同设备之间不共享文件系统。

每个 Agent 实例启动前，MC 会为其生成专属记忆包，并由 ASD / ALCM 挂载到沙箱内：

```text
/sandbox/memory
```

Agent 沙箱只能访问该目录，不能访问：

```text
1. 其他 Agent 的记忆目录
2. 其他 Workflow 的记忆目录
3. 本设备全量长期记忆库
4. 其他设备的本体记忆
```

---

### 0.3 远端调用采用请求方主归属记忆

当设备 A 调用设备 B 的 Agent 时，合作记忆以请求方 A 为主体保存。

```text
1. 请求方合作记忆：
   设备 A 记录“我为了某个任务调用了设备 B 的某个 Agent，远端能力效果如何，
   哪些上下文、约束、参数、失败/成功策略可复用”。

2. 被调用方本地审计 / 自身经验：
   设备 B 只在策略允许时记录“我的某个 Agent 被设备 A 的某个 Workflow 调用，
   执行了什么类型任务，资源消耗与本地 Agent 表现如何”。
```

请求方保存合作记忆的原因是：A 可能只和 B 合作一次。下次 A 在设备 C 上执行相同或相似合作时，A 仍需要复用这次远端协作的经验、参数选择、失败规避和结果评价。

被调用设备可以保存：

```text
1. 调用事实
2. 调用方设备 ID
3. 调用方 Workflow ID
4. 任务类型
5. 执行结果摘要
6. 性能指标
7. 本地 Agent 自身运行经验
```

但合作主体经验、调用方业务上下文、跨设备策略、可迁移协作经验应写回调用方 MC；被调用方不得保存调用方未授权暴露的私有原始记忆、敏感上下文或全量用户记忆。

  * Agent 是否允许接收委派记忆包。

```mermaid
AWM->>ASD: 部署智能体<br>(镜像ID, 资源配置, memory_mount_spec)
ASD->>RRDC: 请求资源列表
RRDC->>ASD: 返回资源列表

ASD->>ALCM: 部署智能体<br>(image_id, resource_config, memory_mount_spec)
ALCM->>RES: 请求资源分配
RES->>ALCM: 资源分配成功

ALCM->>POD: 创建 Agent 沙箱并挂载专属记忆目录<br>/sandbox/memory
POD->>ALCM: 创建成功

ALCM->>ASD: 智能体部署成功<br>(智能体接口)
ASD->>ARDC: 注册智能体实例
ARDC->>ASD: 注册成功
ASD->>AWM: 部署成功

AWM->>POD: 调用 Agent<br>(task_input)
POD->>POD: 读取 /sandbox/memory/input
POD->>POD: 写入 /sandbox/memory/output
POD->>AWM: 返回执行结果

AWM->>MC: 回收 Agent 输出<br>collect_outbox(bundle_id)
MC->>MC: 写入候选记忆<br>(task_result, agent_experience)
MC->>AWM: 写入成功

AWM->>MC: 工作流完成后提交 workflow_summary
MC->>STORE: 写回本体长期记忆
STORE->>MC: 写入成功

AWM->>AOE: 工作流完成
AOE->>APP: 返回编排结果

```

说明：

* Agent 不直接访问 MC 全量记忆库。
* Agent 只访问 `/sandbox/memory`。
* MC 在 Agent 启动前为其生成专属 MemoryBundle。
* Agent 执行后将候选记忆写入 `/sandbox/memory/output`。
* MC 回收 output 后决定是否写入长期记忆。

## 3. 跨主体工作流编排

```mermaid
sequenceDiagram
autonumber

box 设备 A / 调用方本体
    participant A_APP as 1.应用管理层<br>(APP_A)
    participant A_AOE as 2.1 编排引擎<br>(AOE_A)
    participant A_AWM as 2.2 工作流管理<br>(AWM_A)
    participant A_ARDC as 2.4 注册发现<br>(ARDC_A)
    participant A_MC as 2.6 记忆中心<br>(MC_A)
    participant A_STORE as 本体 A 记忆库
end

box 设备 B / 被调用方本体
    participant B_AOE as 2.1 编排引擎<br>(AOE_B)
    participant B_AWM as 2.2 工作流管理<br>(AWM_B)
    participant B_ARDC as 2.4 注册发现<br>(ARDC_B)
    participant B_ASD as 2.3 调度部署<br>(ASD_B)
    participant B_MC as 2.6 记忆中心<br>(MC_B)
    participant B_STORE as 本体 B 记忆库
    participant B_POD as Agent 沙箱<br>(POD_B)
end

A_APP->>A_AOE: 开始编排<br>(指导文件, user_input)

A_AOE->>A_MC: 创建 memory_scope_A
A_MC->>A_STORE: 检索本体 A 相关记忆
A_STORE->>A_MC: 返回候选记忆

A_AOE->>A_ARDC: 请求智能体列表
A_ARDC->>A_AOE: 返回本地 + 远端 Agent 列表

A_AOE->>A_AOE: 拆解任务图
A_AOE->>A_AOE: 判断部分子任务需要调用设备 B 能力

A_AOE->>A_MC: 创建 delegated_memory_bundle<br>(remote_task, target_device_id, target_agent_id)
A_MC->>A_STORE: 检索允许暴露的相关记忆
A_STORE->>A_MC: 返回候选记忆
A_MC->>A_MC: 最小化、脱敏、权限过滤
A_MC->>A_AOE: 返回 delegated_bundle

A_AOE->>B_AOE: 分发子任务图<br>(subtask_graph, delegated_bundle, memory_policy, session_timeout)

B_AOE->>B_ARDC: 请求本地 Agent 列表
B_ARDC->>B_AOE: 返回本地 Agent 列表

B_AOE->>B_MC: 接收远端调用请求<br>(caller_device_id, caller_workflow_id, delegated_bundle)
B_MC->>B_STORE: 检索目标 Agent 本地经验记忆
B_STORE->>B_MC: 返回 agent_memory_excerpt

B_MC->>B_MC: 合并 delegated_bundle 与本地 Agent 经验
B_MC->>B_MC: 生成远端 Agent 沙箱专属记忆目录

B_AOE->>B_AWM: 生成并启动远端工作流<br>(memory_bundle_refs)
activate B_AWM

B_AWM->>B_ASD: 部署远端 Agent<br>(memory_mount_spec)
B_ASD->>B_POD: 创建沙箱并挂载 /sandbox/memory

B_POD->>B_POD: 读取 input/delegated_context
B_POD->>B_POD: 读取 local/agent_memory_excerpt
B_POD->>B_POD: 执行任务
B_POD->>B_POD: 写入 output/result
B_POD->>B_POD: 写入 output/writeback_to_caller<br>(合作经验、结果评价、可复用策略)
B_POD->>B_POD: 写入 output/writeback_to_local<br>(可选：本地审计 / Agent 自身经验)

B_POD->>B_AWM: 返回任务结果
B_AWM->>B_MC: collect_outbox(bundle_id)

B_MC->>B_STORE: 保存允许本地留存的 writeback_to_local<br>(audit_event, local_agent_experience)
B_STORE->>B_MC: 保存成功

B_MC->>B_AWM: 返回 result + writeback_to_caller
B_AWM->>B_AOE: 远端工作流完成
deactivate B_AWM

B_AOE->>A_AOE: 返回远端结果<br>(result, writeback_to_caller)

A_AOE->>A_MC: 保存请求方合作记忆<br>(remote_collaboration_experience, collaboration_memory, reusable_strategy)
A_MC->>A_STORE: 写入本体 A 记忆库
A_STORE->>A_MC: 写入成功

A_AOE->>A_AWM: 生成并启动本地工作流<br>(含远程结果)
A_AWM->>A_APP: 返回最终结果
```

说明：

* 调用方 A 只向 B 发送经过脱敏和最小化的 delegated_memory_bundle。
* 被调用方 B 可以结合自己的本地 Agent Memory 执行任务。
* B 的 Agent 执行后会产生两类写回：

  * `writeback_to_caller`：返回给 A_MC，作为请求方合作记忆的主写回通道，保存远端能力效果、协作策略、可复用经验和失败/成功摘要。
  * `writeback_to_local`：只保存到 B_MC 的本地审计或 B Agent 自身运行经验，不作为跨主体合作经验的主存储。
* B 不保存 A 未授权暴露的私有原始上下文。
* A_MC 后续为 A 调用 C 创建 delegated_memory_bundle 时，可以检索此前 A 调用 B 的合作记忆，用于选择能力、设置约束、复用参数和规避失败策略。

```mermaid
A_AOE->>A_AOE: 拆解新任务图

A_AOE->>A_MC: 创建新的 delegated_memory_bundle<br>(排除 failed_remote)
A_MC->>A_AOE: 返回新委派记忆包

A_AOE->>C_AOE: 分发子任务图<br>(new_subtask, delegated_bundle)
C_AOE->>C_MC: 接收委派记忆包并创建沙箱记忆目录
C_MC->>C_AOE: 创建成功
C_AOE->>A_AOE: 子任务图工作流启动成功

A_AOE->>A_MC: 记录重编排决策<br>(old_remote, new_remote, strategy)
A_MC->>A_AOE: 写入成功

A_AOE->>A_AWM: 停止旧远端工作流引用
deactivate A_AWM

B_AWM->>B_MC: 记录允许本地留存的失败审计<br>(caller_device, workflow_id, failure_reason)
B_MC->>B_MC: 写入本地审计 / Agent 自身运行经验

B_AWM->>B_AOE: 会话超时，停止旧工作流
B_AWM->>B_AWM: 工作流引用次数自减
B_AWM->>B_AOE: 确认停止
deactivate B_AWM

A_AOE->>A_AWM: 生成并启动新工作流<br>(含新远端接口)
activate A_AWM

A_AWM->>A_AOE: 新工作流启动成功
A_AWM->>A_MC: 更新 workflow_summary<br>记录 failover 结果
A_MC->>A_AWM: 更新成功

deactivate A_AWM
```

说明：

* A 侧记录“调用 B 失败，并切换到 C”。
* B 侧只记录策略允许的本地失败审计和自身运行状态。
* C 侧如果执行成功，也只保存策略允许的本地审计；协作成功经验仍回写 A_MC。
* 重编排时 A_MC 的历史失败经验和协作记忆可以影响新的 Agent 选择。

```mermaid
rect rgb(200,250,120)
    A_AOE->>B_AOE: 停止远端工作流<br>(session_id, caller_workflow_id)

    B_AOE->>B_AWM: 停止远端工作流
    B_AWM->>B_MC: 回收远端 Agent 输出<br>(bundle_id)
    B_MC->>B_POD: 收集 /sandbox/memory/output
    B_POD->>B_MC: 返回 result + writeback_to_local + writeback_to_caller

    B_MC->>B_MC: 保存 writeback_to_local<br>本地审计 / Agent 自身运行经验
    B_MC->>B_AWM: 本地保存成功

    B_AWM->>B_AOE: 返回 writeback_to_caller
    B_AOE->>A_AOE: 返回远端停止确认 + writeback_to_caller

    B_AWM->>B_AWM: 工作流引用次数自减
    B_AWM->>B_ASD: 请求关闭远端智能体
    B_ASD->>B_ARDC: 注销远端智能体实例
    B_ARDC->>B_ASD: 确认注销
    B_ASD->>B_AWM: 远端关闭成功
end

A_AOE->>A_MC: 保存远端 writeback_to_caller
A_MC->>A_MC: 写入 remote_collaboration_experience / workflow_summary

A_AOE->>A_MC: 合并本地 + 远端停止摘要
A_MC->>A_AOE: 合并成功

A_AOE->>A_APP: 确认停止
```

说明：

* 远端停止时，B_MC 只保存策略允许的本地审计和 Agent 自身运行经验。
* B_MC 再将调用方可见的 writeback 返回 A_MC。
* A_MC 保存“我调用远端能力的结果、远端协作经验、可迁移策略”。
* B_MC 不作为 A-B 合作记忆的主存储；B_MC 保存“我的 Agent 被远端调用时自身如何运行”的本地记录。

## 8. Agent 沙箱记忆目录规范

每个 Agent 实例只允许访问自己的 `/sandbox/memory`。

```text
/sandbox/memory/
├── manifest.json
├── input/
│   ├── task.md
│   ├── delegated_context.json
│   ├── constraints.json
│   ├── policy.json
│   └── caller_info.json
│
├── local/
│   ├── agent_profile.json
│   ├── agent_memory_excerpt.json
│   └── device_public_context.json
│
└── output/
    ├── result.json
    ├── execution_notes.md
    ├── writeback_to_caller.jsonl
    ├── writeback_to_local.jsonl
    └── artifacts/
```

### 8.1 input 目录

由 MC 生成，Agent 只读。

```text
input/task.md
```

当前任务描述。

```text
input/delegated_context.json
```

调用方允许暴露的上下文。单主体任务中可为空。

```text
input/policy.json
```

当前任务的记忆读写策略。

```text
input/caller_info.json
```

调用方设备、Workflow、Session 信息。单主体任务中 caller 与本设备相同。

---

### 8.2 local 目录

由被调用方本地 MC 生成，Agent 只读。

```text
local/agent_profile.json
```

当前 Agent 的身份、能力、版本、约束。

```text
local/agent_memory_excerpt.json
```

MC 为当前任务抽取的 Agent 本地经验。

```text
local/device_public_context.json
```

本设备允许公开给本地 Agent 的上下文。

---

### 8.3 output 目录

由 Agent 写入，MC 回收。

```text
output/result.json
```

任务执行结果。

```text
output/writeback_to_caller.jsonl
```

返回给调用方 MC 的候选记忆。跨主体任务中，这是合作记忆的主写回通道。

```text
output/writeback_to_local.jsonl
```

写回当前执行方本地 MC 的候选记忆。跨主体任务中仅用于本地审计、资源表现、Agent 自身运行经验，不保存请求方业务上下文或合作主体经验。

## 14. K8s 实现方式

```mermaid
sequenceDiagram
autonumber

participant ASD as ASD
participant MC as MC
participant K8S as K8s API
participant INIT as initContainer
participant AGENT as Agent 容器
participant SIDE as sidecar collector

ASD->>MC: create_bundle(agent_instance_id, task_id)
MC->>ASD: 返回 bundle_id

ASD->>K8S: 创建 Pod<br>(emptyDir + initContainer + sidecar)

K8S->>INIT: 启动 initContainer
INIT->>MC: pull_bundle(bundle_id)
MC->>INIT: 返回 bundle 文件
INIT->>INIT: 写入 /sandbox/memory/input

K8S->>AGENT: 启动 Agent 容器
AGENT->>AGENT: 读取 /sandbox/memory/input
AGENT->>AGENT: 写入 /sandbox/memory/output

K8S->>SIDE: sidecar 监听 output
SIDE->>MC: upload_outbox(bundle_id)
MC->>MC: 暂存、审核、提交候选记忆
```

优点：

```text
1. Agent 不需要直接访问 MC 全量存储
2. 每个 Pod 的 memory 目录天然隔离
3. Pod 销毁后 output 已由 sidecar 回收
4. 不依赖跨 Pod 共享文件系统
```

## 16. 记忆权限策略

远端调用的默认策略：

```json
{
  "allow_callee_local_memory_read": true,
  "allow_callee_save_local_audit": true,
  "allow_callee_save_caller_identity": true,
  "allow_callee_save_delegated_context": false,
  "allow_callee_save_raw_input": false,
  "caller_writeback_allowed": true,
  "local_audit_writeback_allowed": true,
  "caller_owns_collaboration_memory": true
}
```

含义：

```text
1. 允许被调用 Agent 读取自己的本地经验。
2. 允许被调用设备保存“被谁调用、任务类型、资源消耗、本地 Agent 表现”等审计和自身运行信息。
3. 不允许被调用设备保存调用方未授权的私有原始上下文。
4. 调用方接收远端执行结果、协作经验、可复用策略和失败/成功摘要。
5. 跨主体合作记忆归请求方所有；被调用方不作为合作记忆主存储。
```
