### 1 状态管理层

> 核心状态类，贯穿整个系统生命周期

```mermaid
classDiagram
    class MessagesState {
        <<LangGraph基类>>
        +list~Message~ messages
        +add_message()
        +get_last_message()
    }
    
    class State {
        <<Sequential模式>>
        +list~str~ TEAM_MEMBERS
        +bool deep_thinking_mode
        +bool search_before_planning
        +str next
    }
    
    class DistributedState {
        <<分布式编排状态>>
        +int max_retries
        +int timeout_seconds
        +list~AgentInfo~ agent_registry_cache
        +str registry_last_update
        +list~TaskAssignment~ execution_plan
        +int current_task_index
        +bool plan_generated
        +bool all_tasks_completed
        +list~str~ failed_tasks
        +int replanning_count
        +int max_replanning
        +int magentic_round
        +int magentic_stall_count
        +str magentic_mode
        +dict progress_ledger
        +int reset_count
        +str complexity_level
        +str next
    }
    
    class AgentInfo {
        <<智能体信息>>
        +str id
        +str ip
        +int port
        +str capability
        +str status
        +str description
        +list~str~ tags
        +dict metadata
    }
    
    class TaskAssignment {
        <<任务分配>>
        +str task_id
        +str task_title
        +str task_description
        +str assigned_agent_id
        +str target_ip
        +int target_port
        +str status
        +str result
        +int retry_count
        +float start_time
        +float end_time
    }
    
    MessagesState <|-- State : 继承
    MessagesState <|-- DistributedState : 继承
    DistributedState o-- AgentInfo : 包含多个
    DistributedState o-- TaskAssignment : 包含多个
```

**核心职责：**
- **MessagesState**: LangGraph 提供的基类，管理消息历史
- **DistributedState**: 分布式编排的完整状态
  - 支持三种编排模式（Sequential/Concurrent/Magentic-One）
  - 管理智能体注册表缓存
  - 跟踪任务执行计划和进度
  - 支持失败重试和重新规划
- **AgentInfo**: L3 层智能体的注册信息
- **TaskAssignment**: 记录任务分配和执行状态

**文件位置：** `src/graph/distributed_types.py`

**核心职责：**
- **A2AMessage**: 所有 Agent 间通信的标准包装格式
- **A2ATaskRequest**: L2 编排器 → L3 智能体的任务请求
- **A2ATaskResponse**: L3 智能体 → L2 编排器的执行结果
- **A2AClient**: 实现 A2A 协议的异步 HTTP 客户端
  - 支持同步和流式通信
  - 自动重试和超时处理
- **A2AHealthChecker**: 批量健康检查，监控智能体状态

**文件位置：**
- 协议定义: `src/protocols/a2a_protocol.py`
- 客户端实现: `src/service/a2a_client.py`

### 4 编排执行层

> 自适应编排与任务执行

```mermaid
classDiagram
    class AdaptiveOrchestrator {
        <<自适应编排器>>
        +evaluate_task_complexity(task) str
        +evaluate_complexity_by_rules(task) str
        +run_adaptive_workflow(user_input, use_llm_evaluation) dict
        -_select_mode(complexity) str
    }
    
    class UnifiedExecutor {
        <<统一执行器>>
        +str mode
        +StateGraph graph
        +execute(task, mode, config) dict
        +_build_sequential_graph() StateGraph
        +_build_concurrent_graph() StateGraph
        +_build_magentic_graph() StateGraph
        -_get_builder(mode) callable
    }
    
    class ProgressLedger {
        <<进度账本>>
        +ProgressLedgerItem is_request_satisfied
        +ProgressLedgerItem is_in_loop
        +ProgressLedgerItem is_progress_being_made
        +ProgressLedgerItem next_speaker
        +ProgressLedgerItem instruction_or_question
    }
    
    class ProgressLedgerItem {
        <<进度项>>
        +str reason
        +Union answer
    }
    
    class SequentialBuilder {
        <<串行编排>>
        +build() StateGraph
    }
    
    class ConcurrentBuilder {
        <<并行编排>>
        +build() StateGraph
    }
    
    class MagneticOneBuilder {
        <<动态编排>>
        +build() StateGraph
    }
    
    AdaptiveOrchestrator --> UnifiedExecutor : 调用
    UnifiedExecutor ..> SequentialBuilder : 简单任务
    UnifiedExecutor ..> ConcurrentBuilder : 中等任务
    UnifiedExecutor ..> MagneticOneBuilder : 复杂任务
    UnifiedExecutor ..> DistributedState : 使用
    MagneticOneBuilder ..> ProgressLedger : 生成
    ProgressLedger o-- ProgressLedgerItem : 5个维度
```

**核心职责：**
- **AdaptiveOrchestrator**: 自适应编排器
  - 评估任务复杂度（LLM 或规则）
  - 自动选择合适的编排模式
- **UnifiedExecutor**: 统一执行器
  - Sequential: 串行执行，2 次 LLM 调用
  - Concurrent: 并行执行，中等 LLM 开销
  - Magentic-One: 反馈循环，动态智能体选择
- **ProgressLedger**: Magentic-One 的核心组件
  - 每轮生成 5 维度分析
  - 判断任务完成、循环检测、进度评估
  - 动态选择下一个发言者和指令

**编排模式对比：**

| 模式 | 复杂度 | 执行方式 | 智能体选择 | LLM 调用 | 适用场景 |
|------|--------|---------|-----------|---------|---------|
| Sequential | Simple | 串行 | 预定义 | 2次 | 单步任务、简单查询 |
| Concurrent | Medium | 并行 | 预定义 | 中等 | 多角度分析、并行收集 |
| Magentic-One | Complex | 动态循环 | Progress Ledger | 多次 | 研究报告、复杂求解 |

**文件位置：**
- 自适应编排: `src/graph/adaptive_orchestrator.py`
- 统一执行器: `src/graph/unified_executor.py`
- Progress Ledger: `src/graph/progress_ledger.py`
- 图构建器: `src/graph/*_builder.py`
- 执行节点: `src/graph/*_nodes.py`

## 🔄 系统数据流向

### 整体请求流程

```mermaid
sequenceDiagram
    actor User as 用户
    participant API as FastAPI
    participant Adaptive as 自适应编排器
    participant Executor as 统一执行器
    participant Registry as 智能体注册中心
    participant A2A as A2A客户端
    participant L3 as L3智能体
    
    User->>API: POST /api/chat/stream
    API->>Adaptive: 评估任务复杂度
    Adaptive->>Adaptive: LLM/规则评估
    Adaptive->>Executor: 选择编排模式
    
    alt Sequential模式
        Executor->>Registry: 查询智能体
        Registry-->>Executor: AgentInfo列表
        Executor->>Executor: 生成执行计划
        loop 串行执行
            Executor->>A2A: 发送任务请求
            A2A->>L3: HTTP POST
            L3-->>A2A: 任务结果
            A2A-->>Executor: TaskResponse
        end
    else Concurrent模式
        Executor->>Registry: 查询智能体
        Executor->>Executor: 生成执行计划
        par 并行执行
            Executor->>A2A: 任务1
            A2A->>L3: HTTP POST
            and
            Executor->>A2A: 任务2
            A2A->>L3: HTTP POST
            and
            Executor->>A2A: 任务3
            A2A->>L3: HTTP POST
        end
    else Magentic-One模式
        loop Inner Loop (最多20轮)
            Executor->>Executor: 生成Progress Ledger
            alt 任务完成
                Executor->>User: 返回结果
            else 有进展
                Executor->>A2A: 执行next_speaker
                A2A->>L3: HTTP POST
                L3-->>A2A: 结果
                A2A-->>Executor: 更新状态
            else 停滞
                Executor->>Executor: 重置状态
            end
        end
    end
    
    Executor->>API: SSE事件流
    API->>User: 流式返回结果
```

### Magentic-One 详细流程

```mermaid
graph TD
    A[用户请求] --> B[Magentic Planner]
    B --> C[加载Agent Registry]
    C --> D[Orchestrator Inner Loop]
    
    D --> E{生成Progress Ledger}
    E --> F{is_request_satisfied?}
    
    F -->|Yes| G[Reporter生成报告]
    G --> H[返回结果]
    
    F -->|No| I{is_in_loop?}
    I -->|Yes| J{reset_count < max?}
    J -->|Yes| K[重置状态]
    K --> D
    J -->|No| G
    
    I -->|No| L{is_progress_being_made?}
    L -->|Yes| M[执行next_speaker]
    M --> N[Executor调用L3]
    N --> O[更新状态]
    O --> P{round < max_round?}
    P -->|Yes| D
    P -->|No| G
    
    L -->|No| Q[stall_count++]
    Q --> R{stall_count < max_stall?}
    R -->|Yes| D
    R -->|No| G
    
    style D fill:#e1f5fe
    style E fill:#fff3e0
    style F fill:#f3e5f5
    style G fill:#e8f5e9
```

## 编排模式对比

| 维度 | Sequential | Concurrent | Magentic-One |
|------|-----------|------------|--------------|
| **复杂度** | Simple | Medium | Complex |
| **执行方式** | 串行 | 并行 | 动态循环 |
| **智能体选择** | 预定义 | 预定义 | Progress Ledger动态 |
| **LLM调用次数** | 2次 | 5-10次 | 10-50次 |
| **执行时间** | 最快 | 中等 | 较长 |
| **失败处理** | 规则重试 | 规则重试 | LLM重规划 |
| **适用场景** | 简单查询 | 多角度分析 | 复杂研究 |
| **成本** | 最低 | 中等 | 较高 |
| **准确性** | 中等 | 高 | 最高 |

### 场景示例

**Sequential 模式：**

**Magentic-One 模式：**
- ✅ "写一份关于量子计算的深度研究报告"
- ✅ "设计并实现一个完整的Todo应用"
- ✅ "分析并解决一个复杂的系统性能问题"
