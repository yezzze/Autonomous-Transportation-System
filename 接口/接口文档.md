# LangManus 接口文档

本文档从“代码之间的接口契约”视角描述 LangManus 的应用层、编排层、运行层接口。HTTP API、WebSocket、SSE 作为跨进程或对外接口的一部分列出，但不是本文档主体。

---

## 1. 文档范围

本文档覆盖四类接口：

1. Python 类与 public 方法接口
2. 关键函数接口
3. 状态对象、数据模型与配置契约
4. HTTP / WebSocket / SSE 对外接口

不在本文档主体内但会标注的内容：

- 骨架或 Mock 基础设施接口
- Prompt 与模型选择等“非 HTTP 但决定交互边界”的契约

---

## 2. 分层总览

### 2.1 应用层调用链

- DISP / Web UI -> src/api/app.py -> AppManager
- AppManager -> AppLogicEngine
- AppManager -> AgentWarehouse
- AppLogicEngine -> run_distributed_workflow()
- AppLogicEngine -> AgentLifecycleManager

### 2.2 编排层调用链

- run_distributed_workflow() -> build_distributed_graph() 或 build_magentic_graph()
- Graph 节点围绕 DistributedState 读写状态
- distributed_planner_node() -> AgentRegistryClient.query_agents()
- distributed_executor_node() -> UnifiedExecutor 或 dispatch_subtask_to_remote_aoe()
- distributed_monitor_node() -> apply_failure_rules / trigger_llm_replanning
- Magentic 节点 -> create_progress_ledger()

### 2.3 运行层调用链

- AgentLifecycleManager.deploy_agent() -> ResourceRegistry + AgentScheduler
- AgentLifecycleManager.subscribe() / unsubscribe() 管理引用计数
- QoSMonitor.record_call() -> 阈值检查 -> 告警回调
- AgentScheduler.deploy_agent() -> subprocess 启动 agent_server.py -> register_agent()

## 3. 应用层接口

应用层负责“应用”的安装、配置、启动、停止和交互。核心代码位于 src/app 和 src/api/app.py。

### 3.1 数据模型

#### 3.1.1 AppStatus

类型：Literal["idle", "starting", "running", "stopping", "stopped", "error"]

含义：

- idle：已安装但未运行
- starting：启动中
- running：运行中
- stopping：停止中
- stopped：已停止
- error：错误态

#### 3.1.2 AgentImage

位置：src/app/models.py

字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| image_id | str | 镜像唯一标识 |

| version | str | 版本号 |
| capability | str | 能力标签，需与 AgentRegistry capability 对齐 |
| description | str | 描述 |
| exposed_external | bool | 是否允许外部主体使用 |
| metadata | Dict[str, Any] | 扩展元数据 |
| created_at | str | 创建时间 |
| registered | bool | 是否已注册到 ARDC |

核心方法：

- AgentImage.create(name, version, capability, description="", exposed_external=False, metadata=None) -> AgentImage
- AgentImage.to_dict() -> Dict

#### 3.1.3 GuidanceFile

位置：src/app/models.py

字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| app_id | str | 所属应用 ID |
| task_description | str | 编排入口任务描述 |
| agents_required | List[str] | 预部署能力列表 |

- timeout_seconds：工作流超时时间

- max_retries：远端调用重试次数

### 3.2 AppManager 接口

位置：src/app/app_manager.py

角色：应用管理器 APPM，聚合 AW 与 ALRE，维护应用生命周期。

#### 3.2.1 public 方法

- install(name: str, guidance_file: GuidanceFile, images: Optional[List[AgentImage]] = None, expose_external: bool = False) -> AppInfo
- uninstall(app_id: str) -> bool
- start(app_id: str) -> Optional[str]
- stop(app_id: str) -> bool
- get_app(app_id: str) -> Optional[AppInfo]
- list_apps() -> List[AppInfo]
- list_running_apps() -> List[AppInfo]
- update(app_id: str, name: Optional[str] = None, task_description: Optional[str] = None, skills_content: Optional[str] = None, orchestration_mode: Optional[str] = None, constraints: Optional[dict] = None) -> Optional[AppInfo]

#### 3.2.2 调用关系

- install() -> AgentWarehouse.install_agent() -> AppLogicEngine.install_app_logic()
- uninstall() -> AppLogicEngine.uninstall_app_logic() -> AgentWarehouse.uninstall_agent()
- start() -> AppLogicEngine.start_app()
- stop() -> AppLogicEngine.stop_app()
- update() -> 更新 GuidanceFile，并在 skills_content 变化时同步 install_app_logic()

#### 3.2.3 状态变化

- start()：idle/stopped -> starting -> running 或 error
- stop()：running/starting -> stopping -> stopped
- uninstall()：删除 AppInfo 记录，不保留 tombstone

### 3.3 AppLogicEngine 接口

位置：src/app/app_logic_engine.py

角色：应用逻辑执行引擎 ALRE，持有指导文件，负责把应用请求转成编排工作流调用。

#### 3.3.1 public 方法

- install_app_logic(guidance_file: GuidanceFile) -> bool
- uninstall_app_logic(app_id: str) -> bool
- get_guidance(app_id: str) -> Optional[GuidanceFile]
- start_app(app_id: str) -> Optional[str]
- stop_app(app_id: str) -> bool
- is_running(app_id: str) -> bool
- get_workflow_handle(app_id: str) -> Optional[str]
- run_query(app_id: str, user_input: str) -> dict

#### 3.3.2 内部关键接口

- _run_workflow(app_id: str, guidance: GuidanceFile, workflow_handle: str)
- _deploy_and_subscribe(guidance: GuidanceFile, workflow_handle: str) -> List[str]
- _unsubscribe_instances(app_id: str, workflow_handle: Optional[str])
- _register_qos_callback()
- _cancel_remote_session(remote_url: str, session_id: str) -> None

#### 3.3.3 契约说明

start_app()：

1. 读取 GuidanceFile
2. 生成 workflow_handle
3. 调用 _deploy_and_subscribe() 预部署 agents_required 中的能力
4. 使用 asyncio.create_task() 后台执行 _run_workflow()

run_query()：

1. 使用用户输入覆盖 GuidanceFile.task_description
2. 读取 orchestration_mode / constraints / skills_content
3. 若 Skills 含 Pipeline 段，调用 parse_pipeline() 生成 pipeline_topology
4. 调用 run_distributed_workflow()
5. 返回 {workflow_handle, status, result 或 error}

stop_app()：

1. 获取活跃远端会话 get_active_remote_sessions()
2. fire-and-forget 调用 _cancel_remote_session()
3. 取消本地 asyncio.Task
4. 调用 _unsubscribe_instances() 释放引用

## 4. 编排层接口

编排层负责把用户请求转成任务图、执行计划和跨主体调度行为。核心特征是所有节点围绕 DistributedState 流转。

### 4.1 工作流入口

位置：src/distributed_workflow.py

核心函数：

- run_distributed_workflow(user_input: str, debug: bool = False, max_retries: int = 3, timeout_seconds: int = 30, replanning_enabled: bool = True, max_replanning: int = 2, adaptive_mode: bool = True, skills_content: str = "", pipeline_topology: list = [])

契约：

- adaptive_mode=True 时，先调用 evaluate_task_complexity()
- simple -> Sequential Graph
- medium -> 当前降级为 Sequential Graph
- complex -> Magentic-One Graph
- pipeline_topology 非空时跳过复杂度评估，固定 Sequential Graph

返回：Graph 最终 state dict，并补充：

- orchestration_mode
- complexity_level

### 4.2 核心状态对象

位置：src/graph/distributed_types.py

#### 4.2.1 AgentInfo

| 字段 | 类型 | 说明 |
|------|------|------|
| id | str | Agent ID |
| ip | str | IP |
| port | int | 端口 |
| capability | str | 能力标签 |
| status | Literal[online, offline, busy] | 运行状态 |
| description | str | 描述 |

#### 4.2.2 TaskAssignment

### 4.3 Sequential Graph 构图接口

位置：src/graph/distributed_builder.py

核心函数：

- build_distributed_graph()
- build_graph = build_distributed_graph

图结构：

- START -> planner
- planner -> executor 或 __end__
- executor -> monitor
- monitor -> executor 或 reporter
- reporter -> __end__

路由方式：由节点返回 Command.goto 动态控制，而不是静态条件边。

### 4.4 Planner / Executor / Monitor / Reporter 节点接口

位置：src/graph/distributed_nodes.py

#### 4.4.1 Planner

函数签名：

- distributed_planner_node(state: DistributedState) -> Command[Literal["executor", "__end__"]]

读取字段：

- messages
- pipeline_topology
- skills_content

调用接口：

- AgentRegistryClient.query_agents()
- get_llm_by_type("reasoning")

写回字段：

- messages
- execution_plan
- current_task_index
- plan_generated
- all_tasks_completed

特殊分支：

- pipeline_topology 非空时直接生成固定 execution_plan，跳过 LLM Planner
- 无可用 Agent 时直接 goto __end__

#### 4.4.2 Executor

函数签名：

- distributed_executor_node(state: DistributedState)

主要职责：

- 执行当前 task 或并行组
- 路由本地执行与远端执行
- 记录结果、状态和失败信息
- 调用 QoSMonitor 记录质量指标

关键外部接口：

- UnifiedExecutor
- dispatch_subtask_to_remote_aoe()
- get_qos_monitor().record_call()

关键写回：

- execution_plan[*].status / result / retry_count
- current_task_index
- failed_tasks
- failed_cross_host_tasks
- failed_remote_aoe_urls

#### 4.4.3 Monitor

函数签名：

- distributed_monitor_node(state: DistributedState)

主要职责：

- 判断是否完成
- 对失败任务应用 Rule 0 / Rule 1
- 在必要时触发 LLM 重规划
- 决定 goto executor 还是 reporter

关键依赖：

- apply_failure_rules
- trigger_llm_replanning

#### 4.4.4 Reporter

函数签名：

- distributed_reporter_node(state: DistributedState)

主要职责：

- 汇总 messages 与 execution_plan
- 生成最终响应并结束工作流

- health_check(agent_id: str) -> Dict
- get_running_agents() -> List[DeploymentRecord]

- get_deployment(deployment_id: str) -> Optional[DeploymentRecord]

## 6. 跨层共享契约

### 6.1 LLM 选择接口

位置：src/agents/llm.py

核心函数：

- get_llm_by_type(llm_type: LLMType)

支持类型：

- reasoning
- basic
- vision

环境变量来源：src/config/env.py

- REASONING_MODEL / REASONING_BASE_URL / REASONING_API_KEY
- BASIC_MODEL / BASIC_BASE_URL / BASIC_API_KEY
- VL_MODEL / VL_BASE_URL / VL_API_KEY

特殊契约：

- reasoning 路径默认开启 streaming=True
- qwq-plus、o1 系模型需要流式处理
- 全局缓存 _llm_cache 复用实例

### 6.2 能力标签 capability 契约

当前代码中出现的能力标签包括但不限于：

- search
- compute
- vision
- nlp
- code_execution
- web_interaction
- filesystem

说明：

- capability 当前是 str，没有统一枚举类
- GuidanceFile.agents_required、AgentImage.capability、AgentInfo.capability 必须保持语义一致
- Pipeline 解析、注册中心检索、任务重编排都依赖 capability 字符串匹配

### 6.3 Pipeline 拓扑契约

来源：src/app/pipeline_parser.py 与 AppLogicEngine.run_query() / _run_workflow()

约定：

- 若 Skills.md 中包含 Pipeline 段，可解析出 pipeline_topology
- pipeline_topology 非空时，Planner 跳过 LLM，直接生成 execution_plan
- step 可以是串行单步，也可以是并行组 list

### 6.4 Prompt / Progress Ledger 契约

虽然 Prompt 不属于 API，但它定义了模块交互边界：

- Planner Prompt 读取 skills_content、available_agents、用户消息
- Progress Ledger Prompt 固定输出 5 维 JSON
- Orchestrator 依赖 next_speaker 和 instruction_or_question 决定下一步路由
