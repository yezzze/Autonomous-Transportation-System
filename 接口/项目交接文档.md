## 一、项目简介

**LangManus** 是一个基于 LangGraph 的**分布式 Agent 编排系统**，实现了 Microsoft Magentic-One 模式 + 自适应编排模式选择。

核心能力：
- 根据任务复杂度自动选择编排模式（简单/中等/复杂）
- 跨节点 Agent 发现（ARDC Gossip 协议）、分发、故障切换
- 子工作流即服务（多 Agent Pipeline 对外暴露，远端可直接调用）
- 周期性工作流调度（定时触发、并行执行、历史持久化）
- Web UI 管理控制台 + 实时可视化

技术栈：`Python 3.11` + `LangGraph` + `FastAPI` + `httpx` + `asyncio`

## 三、架构概览

### 3.1 三层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  L1 本机工具层  src/tools/                                       │
│    bash、python_repl、search、crawl、browser、file_management    │
├─────────────────────────────────────────────────────────────────┤
│  L2 编排层（本代码库核心）                                        │
│    src/graph/     图构建 + 节点逻辑                                │
│    src/service/   注册表 + 调度器 + 通信客户端                      │
│    src/app/       应用管理 + 指导文件 + Pipeline 解析               │
│    src/api/       FastAPI 端点 + Web UI                           │
├─────────────────────────────────────────────────────────────────┤
│  L3 远端 Agent 层                                                │
│    agent_server.py   E_AOE 节点服务                               │
│    POST /orchestration/dispatch    跨主体任务分发                  │
│    DELETE /orchestration/session/{id}  跨主体会话清理              │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 编排模式

系统根据任务复杂度**自动选择**编排模式（`src/graph/adaptive_orchestrator.py`）：

| 复杂度 | 模式 | 图结构 | 说明 |
|--------|------|--------|------|
| SIMPLE | Sequential | Planner→Executor→Monitor→Reporter | 线性执行，2 次 LLM 调用 |
| MEDIUM | Concurrent | 同上（并发路径开发中） | 中等 LLM 消耗 |
| COMPLEX | Magentic-One | Planner→Orchestrator⇄Executor→Reporter | Progress Ledger 反馈循环 |

如果应用的 Skills.md 中包含 `## Pipeline` 段落，则跳过 LLM Planner 直接按固定拓扑执行。

### 3.3 核心数据流

```
用户请求
  → POST /api/apps/{id}/start
    → AppManager.start()
      → AppLogicEngine.start_app()
        → asyncio.create_task(_run_workflow())
          → run_distributed_workflow()           ← 编排入口
            → evaluate_task_complexity()          ← 自适应模式选择
            → build_distributed_graph() / build_magentic_graph()
            → graph.astream(initial_state)        ← LangGraph 执行
              → Planner → Executor → Monitor → Reporter
```

## 四、核心模块详解

### 4.1 状态定义 — `DistributedState`

文件：`src/graph/distributed_types.py`

所有状态通过 `DistributedState`（TypedDict）流转，**禁止直接 mutate state**，节点通过返回 `dict` 或 `Command(update={...}, goto="next")` 更新状态。

关键字段：

| 字段组 | 字段 | 说明 |
|--------|------|------|
| 执行计划 | `execution_plan: List[TaskAssignment]` | 任务分配列表 |
| | `current_task_index: int` | 当前执行位置 |
| 跨主体 | `cross_host_sessions: Dict[str, str]` | task_id → 远端 AOE URL |
| | `failed_remote_aoe_urls: Dict[str, List[str]]` | 失败节点记录 |
| Magentic | `progress_ledger: dict` | 5 维评估 JSON |
| | `magentic_round / magentic_stall_count` | 轮次和停滞计数 |
| 应用层 | `skills_content: str` | Skills.md 注入内容 |
| | `pipeline_topology: List` | 固定拓扑（空则用 LLM Planner） |

### 4.2 四大节点

文件：`src/graph/distributed_nodes.py`（~1600 行，最核心文件）

| 节点 | 函数 | 职责 |
|------|------|------|
| **Planner** | `distributed_planner_node()` | 查询 ARDC 获取 Agent 列表 + 子工作流列表，生成执行计划。两条路径：Pipeline 快速路径（跳过 LLM）和 LLM 规划路径 |
| **Executor** | `distributed_executor_node()` | 三路径路由执行任务：① 远端跨主体分发 → ② 本地子工作流 → ③ 本地单 Agent。支持并行组 |
| **Monitor** | `distributed_monitor_node()` | 检查任务完成状态，应用故障规则（Rule 0~3），触发重规划 |
| **Reporter** | `distributed_reporter_node()` | 生成最终执行报告 |

**故障规则优先级**：
```
Rule 0 跨主体 failover（最高优先级）
  → 查找替代远端节点，更新 cross_host_sessions
Rule 1 本地重试
  → 跳过已失败的跨主体任务
Rule 2 替换 Agent
  → 同 capability 的备用 Agent
LLM 重规划（兜底）
  → 当所有 Rule 都无法处理时，触发 LLM 重新生成执行计划
```

### 4.3 跨节点编排

**发现**：ARDC HTTP Gossip 协议（`POST /registry/sync`）
- 节点启动时通过 `PEER_AOE_URLS` 加入 Gossip 网络
- 每 30 秒向所有 peer 推送本地 Agent + 子工作流列表
- 120 秒未更新的 peer 自动清理

**分发**：`POST /orchestration/dispatch`
- Planner 调用 `identify_cross_host_tasks()` 识别跨节点任务
- Executor 通过 httpx 将子任务分发到远端 E_AOE
- 远端启动独立工作流实例执行

**停止**：`DELETE /orchestration/session/{id}`
- 本地 `stop_app()` 通知所有远端 E_AOE 取消会话
- 远端 `task.cancel()` 终止工作流

### 4.4 子工作流即服务

**定义**：`config/sub_workflows.json`

```json
{
  "sub_workflows": [{
    "id": "swf_perception_fusion",
    "capability": "perception_fusion",
    "pipeline": [
      {"capability": "perception", "agent_id": "perception_self_001"},
      [  // 并行组
        {"capability": "perception", "agent_id": "perception_vehicleB_001"},
        {"capability": "perception", "agent_id": "perception_vehicleC_001"}
      ],
      {"capability": "cognition", "agent_id": "cognition_main_001"}
    ]
  }]
}
```

- 通过 Gossip 自动发现其他节点的子工作流
- Planner 可选择子工作流分配任务（设置 `sub_workflow_id`）
- Executor 路由：远端跨主体 > 本地子工作流 > 本地单 Agent
- 每次调用启动独立工作流实例

### 4.5 周期性工作流调度

文件：`src/service/workflow_scheduler.py`

- 在 `GuidanceFile.constraints` 中配置 `schedule_interval_seconds`
- `POST /api/apps/{id}/schedule/start` 启动调度
- 每个间隔创建新的 `asyncio.Task` 并行执行（不等上一次完成）
- `schedule_max_parallel` 控制最大并行实例数
- 执行历史持久化到 `data/schedule_history.json`
- `schedule_auto_restart: true` 支持服务重启后自动恢复调度

### 4.6 LLM 三模型体系

文件：`src/agents/llm.py`

```python
from src.agents.llm import get_llm_by_type

reasoning_llm = get_llm_by_type("reasoning")  # 规划/复杂分析
basic_llm     = get_llm_by_type("basic")      # 快速决策
vision_llm    = get_llm_by_type("vision")      # 视觉任务
```

**注意**：`qwq-plus` 模型**只支持 `streaming=True`**，所有节点中的 LLM 调用必须使用 `llm.astream()` 异步流式调用。

## 八、关键约束与注意事项

1. **`qwq-plus` 只支持 streaming=True**：在 `src/agents/llm.py` 中特殊处理；节点中必须使用 `llm.astream()` 异步流式调用
2. **所有节点函数都是 `async def`**：LLM 调用必须用异步方法（`astream`/`ainvoke`），否则会冻结事件循环
3. **禁止直接 mutate state**：通过返回 `dict` 或 `Command(update={...}, goto="...")` 更新
4. **测试必须加 `PYTHONPATH=.`**：否则 import 报错
5. **跨主体通信用 httpx 直连**：不引入 Kafka/MQ
6. **Executor 路由优先级**：远端跨主体 > 本地子工作流 > 本地单 Agent
7. **子工作流内部 Agent 生命周期**由提供方节点自行管理，调用方只关心整体结果

## 十、常见问题

### Q: 如何添加新的 Agent？
编辑 `config/agent_registry.json`，添加新条目，重启服务即可。运行时也可通过 `AgentRegistryClient.register_agent()` 动态注册。

### Q: 如何添加新的子工作流？
编辑 `config/sub_workflows.json`，定义 `id`、`capability`、`pipeline`（串行 `{}` + 并行 `[{},{}]`），重启服务。

### Q: 如何跨节点部署？
1. 在 Node B 上启动 `python agent_server.py 9000`
2. 在 Node A 的 `.env` 中设置 `PEER_AOE_URLS=http://<NodeB_IP>:9000`
3. 启动 Node A：`python server.py`
4. 30 秒后两端 Agent 列表自动同步

### Q: 如何创建定时工作流？
1. 安装应用时在 constraints 中设置 `schedule_interval_seconds`
2. 调用 `POST /api/apps/{id}/schedule/start` 或在 UI 中点击「⏱ 定时启动」
3. 调度器每隔 N 秒自动创建新工作流实例

### Q: 如何调试编排过程？
1. 启动后访问 `http://127.0.0.1:8000/viz` 查看实时可视化
2. 日志中搜索 `[Planner]`、`[Executor]`、`[Monitor]` 关键字
3. 跨主体日志搜索 `[E_AOE]`、`[ARDC Gossip]`

### Q: 测试报 import 错误？
确保命令中包含 `PYTHONPATH=.`：
```bash
PYTHONPATH=. pytest tests/integration/ -v
```
